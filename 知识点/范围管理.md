# 范围管理

## 概述

项目范围管理（Scope Management）是确保项目包含完成项目所需的所有工作（且仅包含这些工作），以成功达成项目目标的过程。它定义了"做什么"和"不做什么"的边界，是项目计划和控制的基础。

## 核心内容

### 范围管理的五个过程

1. **范围规划**：制定范围管理计划，定义如何定义、验证和控制范围
2. **范围定义**：通过工作分解结构（WBS）将项目分解为工作包
3. **创建工作分解结构（WBS）**：将主要可交付成果分解为更小、更易管理的组件
4. **范围确认**：正式接受已完成的可交付成果
5. **范围控制**：管理范围变更，防止范围蔓延（Scope Creep）

### 工作分解结构（WBS）

WBS是范围管理的核心输出物：
- 以**可交付成果**为导向的层次分解
- 最底层工作包应：可估算、可分配、可监控
- 遵循**100%原则**

### 范围确认

范围确认是对已完成的可交付成果进行正式验收的过程：
- 每个里程碑完成时进行确认
- 确认标准在项目计划中预先定义
- 客户/发起人的正式验收是关键

### 范围控制

防止**范围蔓延**（Scope Creep）的关键机制：
- 所有范围变更必须通过正式**变更控制流程**
- 变更控制委员会（CCB）审查和批准变更
- 变更申请 → 影响分析 → CCB审批 → 更新计划 → 实施

### 范围管理中的常见问题

| 问题 | 原因 | 解决方案 |
|------|------|---------|
| 范围蔓延 | 非正式的变更请求 | 强制变更控制流程 |
| 需求镀金 | 超出范围的额外功能 | 专注必要需求 |
| 范围模糊 | 需求不明确 | 加强需求分析和确认 |
