# 质量管理

## 概述

质量管理是确保项目满足其质量要求的过程。根据 GB/T 25000.10—2016 标准，软件质量定义为"在规定条件下使用时，软件产品满足明确或隐含要求的能力"。质量管理包括**质量规划**、**质量保证**和**质量控制**三个核心过程。

## 核心内容

### 软件质量模型

#### 使用质量模型（5个特性）

| 特性 | 含义 |
|------|------|
| 有效性 | 完成任务的能力 |
| 效率 | 使用资源的合理性 |
| 满意度 | 用户满意程度（有用性、可信性、愉悦性、舒适性） |
| 抗风险 | 降低经济、健康安全、环境风险的能力 |
| 周境覆盖 | 适应不同使用环境的能力（完备性、灵活性） |

#### 产品质量模型（8个特性）

| 特性 | 主要子特性 |
|------|-----------|
| 功能性 | 完备性、正确性、适合性 |
| 性能效率 | 时间特性、资源利用性、容量 |
| 兼容性 | 共存性、互操作性 |
| 易用性 | 可辨识性、易学性、易操作性 |
| 可靠性 | 成熟性、可用性、容错性、易恢复性 |
| 信息安全性 | 保密性、完整性、抗抵赖性、可核查性 |
| 维护性 | 模块化、可重用性、易分析性、易修改性、易测试性 |
| 可移植性 | 适应性、易安装性、易替换性 |

#### McCall质量模型

从三个维度考查质量：
- **软件运行**：正确性、可靠性、效率
- **软件修改**：可维护性、灵活性、可测试性
- **软件转移**：可移植性、可重用性、互运行性

### 质量保证（QA）与质量控制（QC）

| | 质量保证（QA） | 质量控制（QC） |
|------|--------------|--------------|
| 关注点 | 过程 | 产品 |
| 目的 | 预防缺陷 | 发现缺陷 |
| 活动 | 评审、审计、过程改进 | 测试、检查、度量 |
| 参与者 | 全员（QA团队主导） | 测试人员为主 |

### 质量管理的八项原则（ISO 9000）

1. 以顾客为关注焦点
2. 领导作用
3. 全员参与
4. 过程方法
5. 管理的系统方法
6. 持续改进
7. 以事实为基础进行决策
8. 与供方互利的关系

### 质量管理工具

- **因果图（鱼骨图）**：分析质量问题的根本原因
- **控制图**：监控过程的稳定性
- **散点图**：分析两个变量的相关性
- **帕累托图（80/20法则）**：识别主要问题
- **检查表**：收集质量数据
