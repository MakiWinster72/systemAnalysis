# 逆向工程

## 概述

软件逆向工程（Reverse Engineering）是一种产品设计技术的再现过程，与传统的正向设计相对。它从已有产品出发，反向推导出设计数据和处理流程。在软件领域，逆向工程可被视为"开发周期的逆行"——根据实现阶段的输出来还原设计阶段的构思。

## 核心内容

### 正向设计 vs 逆向工程

| | 正向设计 | 逆向工程 |
|------|---------|---------|
| 方向 | 构思 → 设计 → 实现 → 产品 | 产品 → 分析 → 设计数据 → 理解 |
| 起点 | 需求规格说明 | 已有产品/代码 |
| 终点 | 可运行的产品 | 可理解的设计模型 |

### 三种主要实现方法

| 方法 | 工具 | 说明 |
|------|------|------|
| **反汇编** | OllyDebug、IDA | 将机器码翻译成汇编代码 |
| **反编译** | 语言特定的反编译器 | 从机器码/字节码重现高级语言源代码 |
| **信息交换分析** | 总线分析器、数据包嗅探器 | 分析通信协议和数据流 |

### 逆向工程的主要工具

- 反汇编工具：OllyDebug、IDA Pro
- 逆向工程软件：Imageware、Geomagic Studio、CopyCAD、RapidForm

### 知识产权与法律问题

- 逆向工程**并不**等同于对知识产权的侵害
- 在特定场景下反而可**保护**知识产权所有者（如集成电路领域的侵权取证）
- 可使用**净室技术**避免版权问题：一组人分析产品编写规格说明，另一组独立人员根据规格说明重写代码
- 各国法律对逆向工程的合法性规定不尽相同

### 软件再工程

逆向工程是**软件再工程**的重要组成部分。再工程是逆向工程的扩充，包括：
1. **再分析**：通过逆向工程理解现有系统
2. **再编码**：基于理解重新实现系统
3. **再测试**：验证新系统的正确性
