# 配置管理

## 概述

配置管理（Configuration Management）是根据国家标准《信息技术 软件工程术语》（GB/T 11457—2006）定义的一套规范，用于标识和确定系统中的配置项，在整个生存周期内控制配置项的投放和更动，记录并报告配置状态和变动要求，并验证配置项的完整性和正确性。其目的是建立和维护工作产品的完整性。

## 核心内容

### 配置管理的六个主要活动

| 活动 | 说明 |
|------|------|
| **1. 编制配置管理计划** | 项目启动时制订，是项目开发计划的组成部分 |
| **2. 配置标识** | 确定配置项内容、命名规范和描述信息（基础性工作） |
| **3. 变更管理和配置控制** | 最重要任务——防止多次变更下失控 |
| **4. 配置状态说明** | 记录和报告配置信息，及时准确给出当前状况 |
| **5. 配置审核** | 验证配置项对配置标识的一致性 |
| **6. 版本控制和发行管理** | 区分配置项版本与配置版本 |

### 配置项（Configuration Item, CI）

可能成为配置项的工作产品包括：
- 系统规格说明书、项目计划、需求规格说明书
- 设计规格说明、源代码、测试用例、测试结果
- 用户手册、操作和安装手册
- 可执行程序、数据库描述
- 软件工程标准和规程

### 基线（Baseline）

基线是软件项目生存期各开发阶段末尾的特定里程碑，用于：
- 检验阶段成果的完整性和正确性
- 作为后续开发的稳定基础
- 控制变更的基准点

### 配置库的三级结构

| 配置库 | 用途 | 访问权限 |
|--------|------|---------|
| **开发库** | 开发过程中的临时存储 | 开发人员读写 |
| **受控库** | 阶段成果受控存储 | 指定人员写入，相关人员读取 |
| **产品库** | 最终交付产品的存储 | 严格控制，极少修改 |

### CMMI中的配置管理九大部分

1. 制订配置管理计划
2. 识别配置项
3. 建立配置管理系统
4. 创建或发行基线
5. 跟踪变更
6. 控制变更
7. 建立配置管理记录
8. 执行配置审核
9. 版本控制

### 版本控制

- 配置项版本：单个文件/工作产品的版本
- 配置版本：一组配置项版本的集合（构成产品版本）
- 版本号规则应统一制定和维护
