# 模式分解

## 概述

模式分解是数据库规范化理论的核心操作，通过将一个存在冗余和异常的关系模式**分解**为多个更小的、满足更高范式级别的子关系模式，以消除数据冗余和操作异常（插入异常、删除异常、修改异常）。

## 核心内容

### 分解的目标与要求

模式分解必须满足两个核心要求：

1. **无损连接性（Lossless Join）**：分解后的子关系通过自然连接能够恢复出原关系的所有信息
   - 形式化定义：$\rho = \{R_1, R_2, ..., R_k\}$ 是 $R$ 的一个分解，若对 $R$ 的任何关系 $r$，有 $r = \pi_{R_1}(r) \bowtie \pi_{R_2}(r) \bowtie ... \bowtie \pi_{R_k}(r)$
   
2. **保持函数依赖（Dependency Preservation）**：原关系中的所有函数依赖在分解后的子关系中仍能被推导
   - 避免在查询时需要跨多个子关系联合验证函数依赖

### 二项分解的无损连接判断

$R$ 分解为 $R_1$ 和 $R_2$，无损连接的充要条件为：
$$(R_1 \cap R_2) \to (R_1 - R_2) \quad \text{或} \quad (R_1 \cap R_2) \to (R_2 - R_1)$$

即公共属性集至少能函数决定其中一个子关系。

### 规范化分解示例

**2NF 分解**（消除部分函数依赖）：
- 选课关系 R(Sno, Cno, Grade, Credit)，候选键 (Sno, Cno)
- 问题：Cno → Credit 是部分函数依赖
- 分解：R1(Sno, Cno, Grade) 和 R2(Cno, Credit)

**3NF 分解**（消除传递函数依赖）：
- 学生关系 S(Sno, Sname, Dno, Dname, Location)
- 问题：Sno → Dno → Dname 是传递依赖
- 分解：S1(Sno, Sname, Dno) 和 S2(Dno, Dname, Location)

**4NF 分解**（消除多值依赖）：
- 产品-部件-测试成绩关系 QY(ypm, bm, sccj)
- 多值依赖：ypm →→ bm，ypm →→ sccj
- 分解：QY1(ypm, bm) 和 QY2(ypm, sccj)

### 关系模式异常的四种表现

| 异常 | 描述 |
|------|------|
| **数据冗余** | 同一信息在多个元组中重复存储 |
| **修改异常** | 修改某信息需同时修改多行，遗漏会导致数据不一致 |
| **插入异常** | 缺少部分信息时无法插入新数据 |
| **删除异常** | 删除某数据时意外丢失其他有用信息 |
