# 并发控制

## 概述

并发控制是DBMS的重要功能，用于协调多个事务同时操作同一数据时保证数据库的完整性，避免数据不一致。其理论基础是**事务的ACID特性**和**可串行化调度**。

## 核心内容

### 事务的ACID特性

| 特性 | 含义 |
|------|------|
| **原子性（Atomicity）** | 事务的操作不可分割，整体执行或全部不执行 |
| **一致性（Consistency）** | 事务使数据库从一个一致状态转到另一个一致状态 |
| **隔离性（Isolation）** | 并发事务互不干扰，结果等价于串行调度 |
| **持久性（Durability）** | 提交后修改永久保存，即使系统故障也不丢失 |

### 并发操作导致的数据不一致

| 问题 | 描述 |
|------|------|
| **丢失修改** | 两事务同时读取并修改同数据，后提交的覆盖先提交的 |
| **读"脏数据"** | 事务A修改数据后被撤销，但事务B已读取了未提交的数据 |
| **不可重复读** | 事务A两次读取间，事务B修改了该数据 |

### 封锁机制

**封锁类型**：
- **X锁（排他锁）**：允许读写，阻止其他任何封锁
- **S锁（共享锁）**：允许并发读取，阻止X锁和修改

**封锁协议**：

| 协议级别 | 可防止的问题 |
|---------|-------------|
| 一级封锁协议 | 丢失修改 |
| 二级封锁协议 | 丢失修改 + 读"脏数据" |
| 三级封锁协议 | 丢失修改 + 读"脏数据" + 不可重复读 |
| 两段锁协议 | **保证可串行化调度** |

### 两段锁协议

- **加锁阶段**（Growing Phase）：只能加锁，不能释放锁
- **解锁阶段**（Shrinking Phase）：只能释放锁，不能加锁

遵守两段锁协议可保证并发调度的可串行化，但可能导致死锁。

### 死锁检测与解除

- **超时法**：事务等待超过预定时间则回滚
- **等待图法**：构建事务等待图，检测环 → 选择代价最小的事务回滚
