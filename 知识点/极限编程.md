# 极限编程

## 概述

极限编程（Extreme Programming, XP）是敏捷方法中最著名的框架，由Kent Beck于1999年提出。它强调将最佳软件开发实践发挥到极致，适用于**小型或中型**软件开发团队，特别是客户需求模糊或多变的项目。

## 核心内容

### 四大核心价值观

1. **沟通（Communication）**：团队成员之间、与客户之间的紧密沟通
2. **简单（Simplicity）**：只做必要的工作，保持设计简洁
3. **反馈（Feedback）**：通过持续测试和频繁交付获得及时反馈
4. **勇气（Courage）**：敢于重构、敢于丢弃不好的代码

### 五大原则

1. **快速反馈**：及时获得系统状态和需求的反馈
2. **简单性假设**：假设最简单的解决方案就是最好的
3. **逐步修改**：通过小的增量变化逐步改进系统
4. **提倡更改**：拥抱变化而非抵制变化
5. **优质工作**：追求高质量的工作成果

### 12个核心实践

| 实践 | 说明 |
|------|------|
| **计划游戏** | 用户故事驱动的迭代计划 |
| **小版本发布** | 频繁交付可工作的软件 |
| **系统隐喻** | 用简单比喻描述系统架构 |
| **简单设计** | 只满足当前需求的设计 |
| **测试驱动开发** | 先写测试再写代码 |
| **重构** | 持续改进代码结构 |
| **结对编程** | 两人共用一台计算机编程 |
| **持续集成** | 频繁合并代码并自动化构建 |
| **集体代码所有制** | 任何人可修改任何代码 |
| **编码标准** | 统一的编程规范 |
| **每周40小时工作制** | 保持可持续的开发节奏 |
| **现场客户** | 客户代表参与开发团队 |

### XP与其他敏捷框架的对比

| 框架 | 侧重 | 适用场景 |
|------|------|---------|
| **XP** | 工程实践（TDD、重构、结对编程） | 需求多变、小团队 |
| **Scrum** | 管理框架（Sprint、Backlog、站会） | 各种规模和类型 |
| **DSDM** | 业务导向（快速交付、业务目标） | 固定时间和资源 |
