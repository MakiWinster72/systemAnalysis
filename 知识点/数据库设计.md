# 数据库设计

## 概述

数据库设计是数据库系统生命周期中的核心阶段，是将业务需求转化为高效、可靠、可维护的数据库结构的过程。设计过程从规划开始，经历需求分析、概念设计、逻辑设计，最终到物理设计。

## 核心内容

### 数据库设计的五个阶段

| 阶段 | 任务 | 产出物 |
|------|------|--------|
| **1. 规划阶段** | 可行性和必要性分析，确定数据库在信息系统中的地位 | 可行性报告 |
| **2. 需求分析阶段** | 调查用户的数据和处理需求 | 需求说明书（含数据字典） |
| **3. 概念设计阶段** | 将需求抽象为不依赖于任何DBMS的概念模型 | **E-R图** |
| **4. 逻辑设计阶段** | 将概念模型转化为特定DBMS支持的逻辑模型 | 关系模式 |
| **5. 物理设计阶段** | 选取适合应用环境的物理存储结构和存取方法 | 物理存储方案 |

### 概念设计 —— E-R模型

**E-R模型**是数据库概念设计的核心工具，由三要素组成：

- **实体（Entity）**：客观存在并可相互区分的事物，用矩形表示
- **属性（Attribute）**：实体的特征，用椭圆形表示
- **联系（Relationship）**：实体间的关联关系，用菱形表示

**联系类型**：
- 一对一（1:1）
- 一对多（1:N）
- 多对多（M:N）

### E-R图向关系模式的转换

1. 每个实体集 → 一个关系模式
2. 1:1联系：可与任意一端合并，或将联系独立
3. 1:N联系：可与N端合并
4. M:N联系：必须独立为一个关系模式，包含两端实体的主键及联系自身的属性

### 数据字典

数据字典是管理**元数据**（关于数据的数据）的核心工具，记录：
- 数据项的名称、类型、长度、取值范围
- 数据结构组成
- 数据流和处理逻辑
- 完整性约束条件
