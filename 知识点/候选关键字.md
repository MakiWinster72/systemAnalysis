# 候选关键字

## 概述

候选关键字（候选码/Candidate Key）是关系数据库中能够唯一标识关系中每个元组的**最小属性组**。候选关键字是数据库设计中进行规范化分析的基础，直接影响关系模式所属的范式级别。

## 核心内容

### 核心概念

| 概念 | 定义 |
|------|------|
| **超键（Super Key）** | 能够唯一标识元组的属性集（可能含冗余属性） |
| **候选键（Candidate Key）** | 最小的超键——不能再去掉任何属性 |
| **主键（Primary Key）** | 从候选键中选定的一个，用于实际唯一标识元组 |
| **外键（Foreign Key）** | 一个关系中的属性，对应另一关系的主键 |
| **主属性** | 包含在任一候选键中的属性 |
| **非主属性** | 不包含在任何候选键中的属性 |

### 函数依赖与候选键

**函数依赖**：设 $R(U)$，$X,Y \subseteq U$。若对任意两个元组 $u,v$，有 $u[X]=v[X] \Rightarrow u[Y]=v[Y]$，则称 $X$ 函数决定 $Y$，记作 $X \to Y$。

**函数依赖类型**：
- **完全函数依赖**：$X \to Y$，且对 $X$ 的任何真子集 $X'$，$X' \to Y$ 不成立
- **部分函数依赖**：$X \to Y$，但 $Y$ 不完全函数依赖于 $X$
- **传递函数依赖**：$X \to Y$（$Y$ 不是 $X$ 的子集），$Y \to Z$

### 图示法求候选键

1. 用**有向图**表示函数依赖（顶点=属性，弧=依赖方向）
2. 找出**入度为0**的属性集作为起点
3. 检查能否从起点遍历所有顶点：
   - 能 → 起点就是候选键
   - 不能 → 逐步加入中间顶点，直到可以遍历全部顶点

### 求候选键的算法

1. 将属性分为四类：
   - **L类**：仅出现在函数依赖左部的属性
   - **R类**：仅出现在函数依赖右部的属性
   - **LR类**：左右部均出现的属性
   - **N类**：左右均未出现的属性
2. L类和N类属性必属于候选键
3. R类属性必不属于候选键
4. 结合LR类属性求最小闭包
