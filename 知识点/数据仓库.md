# 数据仓库

## 概述

数据仓库（Data Warehouse）是面向**决策支持**的独立数据环境，其根本任务是将企业信息加以整理、归纳和重组，并及时提供给管理决策人员。它是一个面向主题的、集成的、非易失的、随时间变化的数据集合。

## 核心内容

### 数据仓库的特征

- **面向主题**：按业务主题（如客户、产品、销售）组织数据
- **集成**：统一命名、编码和属性度量，消除不一致
- **非易失**：数据一旦进入仓库不再修改，仅追加
- **随时间变化**：包含历史快照，支持趋势分析

### ETL过程

ETL（Extraction-Transformation-Loading）是数据仓库建设的核心环节：

1. **抽取（Extraction）**：从OLTP系统、外部数据源和脱机存储介质中获取数据
2. **转换（Transformation）**：对数据进行清洗、关联和转换处理
3. **加载（Loading）**：将处理后的数据集成到数据仓库或数据集市中

### 数据仓库分类

| 类型 | 特点 |
|------|------|
| **企业仓库（Enterprise Warehouse）** | 面向全企业，包含各个主题的详细和汇总数据，可达TB级 |
| **数据集市（Datamart）** | 面向部门级应用，包含企业数据的一个子集 |
| **虚拟仓库（Virtual Warehouse）** | 操作型数据库上视图的集合，易于建立 |

### OLAP与OLTP对比

| 特性 | OLTP（联机事务处理） | OLAP（联机分析处理） |
|------|---------------------|---------------------|
| 用户 | 操作员、DBA | 决策者、分析师 |
| 功能 | 日常操作 | 决策支持 |
| 数据 | 当前、最新 | 历史、汇总 |
| 操作 | 简单查询和更新 | 复杂分析查询 |
| 数据量 | GB级 | TB级 |

### 数据仓库的设计方法

- **自顶向下**：先建立企业级数据仓库，再衍生各部门数据集市
- **自底向上**：先从最关键需求开始建立数据集市，逐步扩充和完善
- **混合法**：结合两种方法的优点
