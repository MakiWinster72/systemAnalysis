# 安全体系

## 概述

信息系统安全体系是将安全策略、安全技术、安全管理和安全评估整合为统一框架的系统工程。一个全面的信息系统安全体系覆盖物理安全、网络安全、系统安全、应用安全和数据安全等多个层面，目标是实现信息的**机密性、完整性、可用性、可控性和不可否认性**。

## 核心内容

### 安全体系的层次结构

| 层次 | 内容 |
|------|------|
| **物理安全** | 机房、设备、线路的物理保护 |
| **网络安全** | 防火墙、IDS/IPS、VPN、安全协议 |
| **系统安全** | 操作系统加固、补丁管理、防病毒 |
| **应用安全** | 身份认证、访问控制、代码安全 |
| **数据安全** | 加密存储、备份恢复、数据防泄漏 |
| **安全管理** | 安全策略、人员管理、安全审计 |

### 访问控制模型

| 模型 | 核心原则 | 目标 |
|------|---------|------|
| **BLP模型（Bell-LaPadula）** | 上读下写：不上读（No Read Up）、不下写（No Write Down） | **保密性** |
| **Biba模型** | 下读上写：不下读（No Read Down）、不上写（No Write Up） | **完整性** |
| **RBAC（基于角色）** | 用户→角色→权限，通过角色实现灵活访问控制 | 通用访问控制 |
| **Lattice模型** | 安全级格，多边安全 | 信息流控制 |

### 访问控制分类

| 类型 | 说明 | 特点 |
|------|------|------|
| **DAC（自主访问控制）** | 资源所有者决定访问权限 | 灵活 |
| **MAC（强制访问控制）** | 系统根据安全标签强制执行 | 严格 |
| **RBAC（基于角色）** | 权限通过角色分配 | 易于管理 |
| **TBAC（基于任务）** | 权限随任务上下文动态变化 | 动态 |
| **OBAC（基于对象）** | 权限与对象关联 | 细粒度 |

### 网络安全设计原则

1. **木桶原则**：安全强度取决于最弱环节
2. **整体性原则**：各安全组件协同形成完整防护链
3. **等级性原则**：根据信息敏感度分级保护
4. **设计为本原则**：安全在设计阶段融入而非后期修补
5. **自主与可控原则**：安全技术和产品可控

### 安全评估标准

| 标准 | 说明 |
|------|------|
| **TCSEC（橙皮书）** | 美国国防部可信计算机系统评估标准 |
| **ITSEC** | 欧洲信息技术安全评估标准 |
| **CC（通用准则）** | ISO/IEC 15408，国际通用安全评估标准 |
| **GB 17859** | 中国计算机信息系统安全保护等级划分 |

### 安全管理核心内容

- **密码管理**：密钥的生成、分发、存储和销毁
- **网络管理**：防火墙策略、入侵检测、访问控制
- **设备管理**：设备安全配置和物理保护
- **人员管理**：安全意识培训、权限审查、离职管理
