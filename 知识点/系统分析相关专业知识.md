# 系统分析相关专业知识

## 概述

系统分析是信息系统建设的关键环节，是连接业务需求与技术实现的桥梁。系统分析师需要具备全面的专业知识体系，涵盖**系统理论、需求工程、架构设计、软件工程、项目管理、信息安全**等多个领域，并在实际工作中发挥沟通、协调和技术决策的核心作用。

## 核心内容

### 系统分析师的角色定位

系统分析师是信息系统建设的核心人物，需兼具**IT专家**和**管理业务专家**双重角色：

| 角色 | 职责 |
|------|------|
| 沟通桥梁 | 在业务用户和技术团队之间传递和转化需求 |
| 谈判代表 | 在不同利益方之间协调和平衡 |
| 技术负责人 | 主导系统架构设计和技术选型 |

### 系统分析师的五大任务领域

1. **战略管理**：参与信息化战略规划，确保IT与业务对齐
2. **基础建设**：信息基础设施规划、标准化和安全管理
3. **系统开发**：需求分析、架构设计、实施监督
4. **流程管理**：业务流程分析与优化（BPR、BPM）
5. **信息资源管理**：数据治理、知识管理和信息资源规划

### 核心知识体系

#### 系统工程方法论

| 方法 | 特点 |
|------|------|
| **霍尔三维结构（硬系统）** | 时间维、逻辑维、知识维三维框架，适用于目标明确的系统 |
| **切克兰德软系统方法论** | 适用于目标不明确、涉及社会因素的"软"问题 |

#### 需求工程

- **需求层次**：业务需求 → 用户需求 → 系统需求（FURPS+分类）
- **需求获取方法**：用户访谈、问卷调查、联合需求计划（JRP）、用户故事
- **需求分析方法**：结构化分析（DFD+数据字典）、面向对象分析（用例模型+分析模型）
- **需求定义**：严格定义法、原型法

#### 系统设计

- **结构化设计（SD）**：模块结构设计、系统结构图（SC）
- **面向对象设计（OOD）**：六大设计原则（单一职责、开闭、里氏替换、依赖倒置、接口隔离、迪米特）
- **设计模式**：GoF 23种经典设计模式（创建型、结构型、行为型）

#### 架构设计

- **架构风格**：数据流、调用/返回、独立构件、虚拟机、以数据为中心
- **架构评估**：ATAM、SAAM（基于质量属性场景的评估方法）
- **质量属性**：性能、可靠性、可用性、安全性、可修改性、功能性、可变性、互操作性

### 专业能力要求

| 能力维度 | 要求 |
|---------|------|
| **分析能力** | 能从复杂业务场景中抽象出问题本质 |
| **建模能力** | 熟练使用各种建模工具（DFD、E-R图、UML等） |
| **沟通能力** | 与业务和技术人员有效沟通 |
| **决策能力** | 在多个方案中做出最优选择 |
| **学习能力** | 持续学习新技术和新方法 |

### 系统可行性分析

| 分析维度 | 核心问题 |
|---------|---------|
| **技术可行性** | 现有技术能否实现系统？ |
| **经济可行性** | 收益是否大于成本？（NPV、ROI、投资回收期） |
| **法律可行性** | 是否违反法律法规？ |
| **操作可行性** | 用户是否接受新系统？ |
| **进度可行性** | 能否在规定时间内完成？ |
