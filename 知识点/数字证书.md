# 数字证书

## 概述

数字证书（Digital Certificate）是由**认证中心（CA）** 签发的公钥认证，遵从X.509国际标准。它通过将公钥与持有者身份绑定，解决了公钥分发中的信任问题，是PKI（公钥基础设施）的基石。

## 核心内容

### X.509数字证书内容

| 字段 | 说明 |
|------|------|
| 版本号 | X.509版本（通常为v3） |
| 序列号 | CA分配的唯一编号 |
| 签名算法标识符 | 如 SHA-256 with RSA |
| 发行者（Issuer） | 签发此证书的CA名称 |
| 有效期（Validity） | 证书的生效日期和失效日期 |
| 主体（Subject） | 证书持有者名称 |
| 主体公钥信息 | 持有者的公钥和算法 |
| 扩展信息 | 密钥用途、CRL分发点等 |
| CA数字签名 | CA用其私钥对以上字段的签名 |

### 认证中心（CA）

CA是PKI的核心，负责：
- 验证证书申请者的身份
- 签发和发布数字证书
- 管理证书生命周期（更新、吊销）
- 发布**证书撤销列表（CRL）**

### 证书链与信任模型

由于不同CA签发的证书需要互认，形成了证书链：

```
根CA（自签名，绝对信任）
    ↓ 签名
  中间CA
    ↓ 签名
  终端实体证书（如Web服务器证书）
```

- 客户端通过逐级验证CA签名，构建信任链
- 浏览器和操作系统预置了受信任的**根CA列表**

### 证书撤销列表（CRL）

当私钥泄露或持有者信息变更时，CA将证书序列号加入CRL。验证方应检查：
1. 证书是否在有效期内
2. 证书是否在CRL中
3. 证书链是否完整可信

**OCSP**（在线证书状态协议）是CRL的实时替代方案。

### 三种密钥管理体制

| 体制 | 说明 |
|------|------|
| **KMI（密钥管理基础设施）** | 基于对称密钥的集中式管理 |
| **PKI（公钥基础设施）** | 基于非对称密钥和证书，应用最广泛 |
| **SPK（种子化公钥）** | 基于标识的密钥生成，减少证书管理复杂度 |

### 数字证书的典型应用

- **HTTPS**：Web服务器身份认证和TLS会话密钥交换
- **代码签名**：验证软件发布者的身份和代码完整性
- **电子邮件**：S/MIME邮件签名和加密
- **VPN**：IPSec/IKE中的设备认证
- **电子政务/电子商务**：企业身份认证和电子签章
