# 死锁与银行家算法

## 概述

死锁（Deadlock）是指两个或多个进程在执行过程中，因互相等待对方所占有的资源而陷入无限等待的状态。银行家算法（Banker's Algorithm）是 Dijkstra 提出的一种**死锁避免**算法，通过判断系统是否处于安全状态来决定是否分配资源。

## 核心内容

### 死锁产生的四个必要条件

1. **互斥条件**：资源每次只允许一个进程使用
2. **不剥夺条件**：进程已占用的资源不会被强制剥夺
3. **请求与保持条件**：进程请求新资源时不主动释放已占资源
4. **环路条件**：存在进程-资源的循环等待链

> 四个条件必须同时满足才会产生死锁，破坏任一条件即可预防死锁。

### 死锁处理策略

| 策略 | 说明 | 方法 |
|------|------|------|
| **预防** | 破坏四个必要条件之一 | 预先静态分配法、资源有序分配法 |
| **避免** | 分配资源前判断安全性 | **银行家算法** |
| **检测与解除** | 允许死锁发生再处理 | 资源剥夺法、撤销进程法 |

### 银行家算法

**核心思想**：在分配资源前，先模拟分配后是否还有安全序列可用。如果存在安全序列（即所有进程都能顺利完成），则资源分配是安全的；否则拒绝分配。

**数据结构**：
- **Available**：系统当前可用资源向量
- **Max**：每个进程对各类资源的最大需求矩阵
- **Allocation**：每个进程当前已分配的资源矩阵
- **Need**：每个进程还需的资源矩阵（Need = Max - Allocation）

**安全性检查步骤**：
1. 设置 Work = Available，Finish[i] = false
2. 寻找满足 Finish[i] = false 且 Need[i] ≤ Work 的进程
3. 若找到，则 Work = Work + Allocation[i]，Finish[i] = true
4. 重复步骤2-3，直至所有 Finish[i] = true（安全）或找不到满足条件的进程（不安全）

### 死锁与PV操作的关系

PV操作是实现进程同步互斥的重要工具，但使用不当会导致死锁：
- P操作顺序不一致可能导致环路等待
- 对多个信号量同时执行P操作时如果顺序不当，可能死锁
- V操作遗漏会导致资源无法释放，进程永久阻塞
