# 摘要与数字签名

## 概述

摘要与数字签名是现代密码学中的核心认证技术。**消息摘要**通过哈希函数将任意长度的消息转换为固定长度的"指纹"，用于验证数据完整性；**数字签名**则利用非对称加密技术实现消息的不可否认性和来源认证。

## 核心内容

### 哈希（Hash）函数与消息摘要

哈希函数将**任意长度**的输入映射为**固定长度**的输出（消息摘要/MD），具有以下特性：

| 特性       | 说明                 |
| -------- | ------------------ |
| **单向性**  | 从摘要无法反推出原始消息       |
| **抗碰撞性** | 难以找到两个不同的消息产生相同的摘要 |
| **固定输出** | 无论输入多长，输出固定长度      |
| **雪崩效应** | 输入微小变化导致输出完全不同的摘要  |

### 主要哈希算法

| 算法          | 输出长度 | 安全性   | 状态        |
| ----------- | ---- | ----- | --------- |
| **MD5**     | 128位 | 已破解   | **不推荐使用** |
| **SHA-1**   | 160位 | 已发现碰撞 | **不推荐使用** |
| **SHA-256** | 256位 | 安全    | 广泛使用      |
| **SHA-512** | 512位 | 安全    | 高安全场景     |
| **SM3**     | 256位 | 安全    | 中国国家密码标准  |

### 数字签名

数字签名是附加在数据单元上的密码变换，用于确认数据来源和完整性，防止伪造和抵赖。

**三大安全保证**：
1. **鉴别**：接收者可核实发送者签名
2. **不可否认**：发送者事后不能否认发送
3. **完整性**：接收者不能伪造签名

**签名过程**：
```
发送方：消息 → Hash → 消息摘要 → 用私钥加密 → 数字签名
发送：消息 + 数字签名

接收方：收到消息 → Hash → 消息摘要A
        用发送方公钥解密签名 → 消息摘要B
        比较 A == B → 验证通过/失败
```

### 数字签名标准

| 标准 | 算法 | 特点 |
|------|------|------|
| **RSA签名** | RSA + SHA | 最广泛使用 |
| **DSA** | DSA（仅签名，不含加密）| 美国联邦标准 |
| **ECDSA** | 椭圆曲线DSA | 高效，移动端友好 |
| **SM2** | 基于ECC | 中国国家密码标准 |

### 消息认证码（MAC）

- 使用**对称密钥** + 哈希函数的消息认证机制
- 需要双方共享密钥
- 不提供不可否认性（双方都能生成）
- HMAC是常用实现

| | MAC | 数字签名 |
|------|-----|---------|
| 密钥 | 对称密钥 | 非对称密钥（私钥签名） |
| 不可否认 | ❌ | ✓ |
| 速度 | 快 | 慢 |
