# 净室工程

## 概述

净室软件工程（Cleanroom Software Engineering, CSE）是软件开发的一种**形式化方法**，通过严格的工程规范和统计质量控制来开发高质量软件。其核心理念是：**在开发过程中预防缺陷**，而非在测试阶段发现和修复缺陷。

## 核心内容

### 核心理念

- **缺陷预防**优于缺陷检测：通过形式化方法避免引入缺陷
- **统计质量控制**：使用统计方法评估和控制软件质量
- **增量开发**：分阶段交付，逐步验证
- **使用净室技术**来避免侵犯版权（两个独立的开发团队不互相参考实现）

### 主要实践

1. **形式化规格说明**：使用数学方法精确定义系统行为
2. **逐步求精**：从抽象规格说明逐步推导出具体实现
3. **结构化的正确性验证**：在编码前通过数学推理验证设计正确性
4. **统计测试**：基于使用模型生成测试用例，统计评估可靠性
5. **独立的测试团队**：开发与测试严格分离

### 净室工程与传统开发的对比

| 特性 | 传统开发 | 净室工程 |
|------|---------|---------|
| 质量理念 | 通过测试发现和修复缺陷 | 在开发过程中预防缺陷 |
| 开发方式 | 编码→测试→修复 | 形式化设计→验证→编码 |
| 测试角色 | 开发人员自测 | 独立测试团队 |
| 度量标准 | 缺陷密度 | 统计可靠性增长 |
| 适合场景 | 一般商业软件 | 高可靠性系统 |

### 与逆向工程的关系

净室技术可用于软件逆向工程中避免版权问题：
- 一组工程师分析原有产品，编写规格说明
- 另一组（独立的、未接触原产品的）工程师根据规格说明实现新产品
- 两组人员严格隔离，确保新产品不包含原产品的版权元素

### 应用场景

- 航空航天控制系统
- 医疗设备软件
- 核电站控制系统
- 金融交易系统
- 任何对可靠性要求极高的系统
