# Web应用系统部署

## 概述

Web应用部署是将已构建完成的Web应用发布到服务器上，通过配置运行环境使用户可通过Internet访问。部署过程包括打包、发布和评估三个环节。

## 部署粒度

Web应用采用增量迭代开发，部署也会频繁发生。发布可以细粒度方式进行（组件测试后立即发布），也可将一组变化打包发布。

**灰度发布策略**：Web应用升级伴随新旧版本兼容、用户习惯改变、系统宕机等风险。灰度发布将影响集中到一个点，再发散到面，出现意外可快速回退，以用户反馈作为改进依据。

## 部署原则

1. **管理客户期望**：与客户有效沟通，不轻易做出可能无法完成的承诺，敏捷方法支持增量交付
2. **全面测试**：在不同硬件平台、浏览器配置、网络带宽、安全设置下完整测试
3. **建立支持制度**：准备支持过程和响应机制，建立记录保持机制
4. **先改缺陷再交付**：交付低质量增量不妥，应收集用户反馈并及时调整开发计划

## 部署环境

### 操作系统
- Windows Server系列、Linux、各类UNIX
- Windows XP仅用于开发测试

### Web服务器软件
- Apache、IIS（仅Windows）、Websphere、Weblogic

### 应用服务器关键功能
- **[[负载均衡]]**：基于进程或线程方式实现
- **数据库连接池**：采用连接池技术提高性能
- **高速缓存机制**：提升系统响应速度

## 版本控制与CMS

版本控制和[[内容管理系统]]在变更管理中起重要作用：
- 确保发布内容正确且一致
- 控制和跟踪内容变更
- 验证功能版本及对应关系
- 系统失败时快速重建
- 支持版本回滚

随着Web应用规模扩大，全面版本控制和健壮CMS的要求也在增加。
