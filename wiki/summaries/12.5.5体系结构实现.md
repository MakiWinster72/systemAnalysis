# 体系结构实现与演化

## 概述

本章节系统阐述了软件体系结构从文档化到实现的完整流程，以及体系结构演化的六步法。内容涵盖[[体系结构文档化]]、[[体系结构复审]]、[[体系结构实现]]和[[体系结构演化]]四个关键阶段。

## 核心概念

### 12.5.3 体系结构文档化

体系结构是抽象的概念性构件，需要文档化以便开发人员实现。主要输出两个文档：
- **体系结构规格说明**
- **测试体系结构需求的质量设计说明书**

文档要求：
- 从使用者角度编写
- 分发给所有相关开发人员
- 保证开发者持有最新版本

### 12.5.4 体系结构复审

体系结构设计、文档化和复审是**迭代过程**。复审特点：
- 由外部人员（用户代表和领域专家）参加
- 通常搭建最小化可运行系统进行评估

复审目的：识别潜在风险，发现设计缺陷和错误

### 12.5.5 体系结构实现

**实现**的三个核心要求：
1. 符合体系结构描述的结构性设计决策
2. 分割成规定的[[构件]]
3. 按规定方式互相交互

实现过程：
```
复审后的文档化的体系结构
    ↓
分析与设计 → 构件实现 → [[构件库]] → [[构件组装]] → 系统测试
    ↓
体系结构演化
```

关键点：
- 以复审后的文档化体系结构说明书为基础
- [[构件]]必须满足对其他构件的责任
- 接口约束是构件的唯一外部代表
- 可从构件库查找符合接口约束的构件
- 最后进行功能性测试和整体性能测试

### 12.5.6 体系结构的演化

当需求变动或系统移植时，需要修改体系结构。演化六步法：

| 步骤 | 内容 |
|------|------|
| 1 | 需求变化归类，与已有构件对应 |
| 2 | 制订体系结构演化计划 |
| 3 | 修改、增加或删除[[构件]] |
| 4 | 更新构件的相互作用 |
| 5 | 构件组装与测试 |
| 6 | 技术评审 |

## 关键要点

1. **文档是通信媒介**：在系统演化每个阶段，文档是设计与开发人员的主要沟通工具
2. **迭代改进**：设计→文档化→复审形成迭代循环
3. **接口约束驱动**：构件通过接口约束定义，便于复用和组装
4. **演化闭环**：所有修改必须集成回原体系结构，完成完整演化过程
