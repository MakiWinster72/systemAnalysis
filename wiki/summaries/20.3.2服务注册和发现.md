## 服务注册与发现

### 概述

服务注册与发现是[[微服务架构]]中的关键环节，通过注册中心实现服务提供者与消费者的解耦，保证系统的高可用性和扩展性。

### 核心原理

- 服务提供者将自身信息注册到注册中心
- 服务消费者从注册中心获取服务信息进行调用
- 实现了服务间的松耦合

### 主要技术

#### Consul

分布式服务注册与发现工具，主要功能包括：

- **服务注册**：客户端将服务元数据（名称、地址、端口）注册到服务器
- **服务发现**：支持 DNS 或 HTTP 方式查询可用服务
- **健康检查**：定期检查服务运行状态，自动标记不可用服务
- **多数据中心**：支持跨地域部署，提升容错性
- **KV 存储**：分布式配置数据存储与共享

#### ZooKeeper

Apache 开发的分布式协调服务，采用 [[ZAB 协议]]保证数据一致性：

- **数据模型**：类似文件系统的 Znode 结构，数据存储于内存
- **核心特性**：高可用、高性能、严格一致性
- **高级功能**：Watches 机制实现实时通知，ACL 权限控制
- **应用场景**：分布式锁、选举、配置管理

#### Eureka

Netflix 开发的基于 REST 的服务治理框架：

- **Eureka Server**：服务注册中心，维护服务实例清单
- **Eureka Client**：服务实例，定期发送心跳包保持连接
- **剔除机制**：心跳超时服务实例会被自动剔除
- **集成能力**：可与 Ribbon、Hystrix 等组件无缝集成

#### Etcd

CNCF 孵化的高可用键值存储系统：

- **协议**：基于 [[Raft 协议]]实现的分布式存储
- **功能**：支持 CRUD 操作、事务操作、监听机制
- **应用**：Kubernetes 集群默认数据存储和服务发现组件
- **特点**：每个节点存储完整数据，通过 Raft 协议同步

### 对比总结

| 技术 | 特点 | 适用场景 |
|------|------|----------|
| Consul | 多功能集成 | 跨数据中心部署 |
| ZooKeeper | 强一致性 | 配置管理与协调 |
| Eureka | RESTful 风格 | Spring Cloud 生态 |
| Etcd | 高可用键值 | Kubernetes 集群 |
