# 调用/返回体系结构风格

调用/返回体系结构风格是指在系统中采用调用与返回机制，利用分而治之策略将复杂大系统分解为若干子系统，以降低复杂度并增加可修改性。程序从执行起点开始执行构件代码，结束后将控制返回给调用构件。

## 四种主要风格

### 1. 主程序/子程序风格
- 采用单线程控制，将问题划分为若干处理步骤
- 构件即为主程序和子程序，子程序可合成为模块
- 过程调用作为交互机制（连接件）
- 调用关系具有层次性，子程序正确性取决于其调用的子程序正确性

### 2. 面向对象体系结构风格
- 建立在数据抽象和面向对象基础上
- 数据的表示方法和相应操作封装在抽象数据类型或对象中
- 构件是对象（抽象数据类型的实例）
- 通过过程调用进行交互

### 3. 层次型体系结构风格
- 采用层次结构，每层为上层提供服务，作为下层客户
- 除精选的输出函数外，内部层接口只对相邻层可见
- 构件在层上实现虚拟机
- 连接件由层间交互协议定义
- 拓扑约束包括相邻层间交互约束
- 支持软件重用：每层可用不同方法实现，只要提供相同接口

### 4. 客户端/服务器（C/S）体系结构风格

#### 二层C/S架构
- 20世纪90年代成熟，基于资源不对等和共享需求
- **胖客户机、瘦服务器模式**
- 优点：功能构件充分隔离、硬件软件适应性强、易于扩充、可分布处理
- 缺点：
  - 开发成本高
  - 客户端程序复杂庞大
  - 用户界面风格不一
  - 软件移植困难
  - 维护和升级困难
  - 新技术应用受限
  - 可扩展性差
  - 安全性难以保证

#### 三层C/S架构
增加应用服务器，将应用逻辑驻留在服务器上，客户机变瘦。分为三层：

| 层级 | 职责 |
|------|------|
| **表示层** | 用户接口，对话功能，数据检查，显示控制 |
| **功能层** | 业务逻辑处理，如计算、配置、打印等 |
| **数据层** | DBMS管理和控制 |

三层架构优点：
- 逻辑独立，提高可维护性和可扩展性
- 灵活选用平台和硬件
- 各层可并行开发，选择适合的开发语言
- 中间件是最重要构件

物理部署方式：
- 数据层和功能层放在同一服务器
- 数据层和功能层放在不同服务器
- 功能层放在客户机上
