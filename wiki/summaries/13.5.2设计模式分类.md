# 设计模式分类总结

## 概述

设计模式是对软件设计中普遍存在（反复出现）的各种问题所提出的解决方案，是经在前人系统中得以证实并广泛使用的技术。每种设计模式都是对[[面向对象设计原则]]的体现。

## 设计模式的四大关键元素

设计模式包含**模式名称**、**问题**、**解决方案**、**效果**四个关键元素：

1. **模式名称**：助记名，用一两个词语描述模式解决的问题、方案和使用效果
2. **问题**：描述何时使用模式，包括使用模式必须满足的先决条件
3. **解决方案**：描述设计的组成成分、关系及职责协作方式，提供抽象描述和元素组合
4. **效果**：描述模式应用的优缺点，包括时间空间权衡、对系统灵活性和可扩展性的影响

## 设计模式分类

### 按目的和用途分类

| 类别 | 用途 | 主要模式 |
|------|------|----------|
| **创建型模式** | 抽象对象创建过程，实现对象创建与组织独立 | 工厂方法、抽象工厂、原型、单例、建造者 |
| **结构型模式** | 处理类或对象的组合形成更大结构 | 适配器、桥接、组合、装饰、外观、享元、代理 |
| **行为型模式** | 描述类或对象的交互及职责分配 | 职责链、命令、解释器、迭代器、中介者、备忘录、观察者、状态、策略、模板方法、访问者 |

### 按处理范围分类

- **类模式**：处理类和子类关系，通过继承建立，在编译时刻确定（静态关系）
- **对象模式**：处理对象关系，在运行时刻变化（动态关系）

## 创建型模式详解

| 模式 | 别名 | 特点 |
|------|------|------|
| [[工厂方法模式]] | 虚拟构造器/多态模式 | 父类定义创建接口，子类决定实例化哪个类 |
| [[抽象工厂模式]] | Kit模式 | 提供创建一系列相关对象的接口，引入产品等级结构和产品族概念 |
| [[原型模式]] | - | 通过复制原型对象创建同类对象，支持浅克隆和深克隆 |
| [[单例模式]] | - | 确保类只有一个实例，提供全局访问 |
| [[建造者模式]] | - | 分离复杂对象构建与表示，支持不同表示 |

## 结构型模式详解

| 模式 | 别名 | 特点 |
|------|------|------|
| [[适配器模式]] | - | 将一个接口转换成客户希望的另一个接口，支持类适配和对象适配 |
| [[桥接模式]] | 柄体/接口模式 | 分离抽象与实现，独立变化，比多重继承更灵活 |
| [[组合模式]] | 整体-部分模式 | 树形结构表示整体-部分，单个与组合对象使用一致 |
| [[装饰模式]] | - | 动态给对象增加职责，比生成子类更灵活 |
| [[外观模式]] | - | 为子系统定义统一高层接口，简化使用 |
| [[享元模式]] | - | 运用共享技术支持大量细粒度对象，区分内部/外部状态 |
| [[代理模式]] | - | 为对象提供代理控制引用，协调调用者和被调用者 |

## 行为型模式详解

| 模式 | 别名 | 特点 |
|------|------|------|
| [[职责链模式]] | - | 将对象连成链传递请求直到被处理 |
| [[命令模式]] | - | 将请求封装为对象，支持参数化、排队、日志和撤销 |
| [[解释器模式]] | - | 定义语言文法和解释句子，主要用于编译器 |
| [[迭代器模式]] | - | 访问聚合对象不暴露内部，支持多种遍历方式 |
| [[中介者模式]] | - | 通过中介对象封装对象交互，松散耦合 |
| [[备忘录模式]] | - | 捕获对象内部状态用于恢复，保证封装 |
| [[观察者模式]] | 发布-订阅模式 | 定义一对多依赖关系，状态改变时自动更新依赖 |
| [[状态模式]] | - | 内部状态改变时改变行为，看起来修改了类 |
| [[策略模式]] | - | 定义一系列可互换的算法，算法独立于客户 |
| [[模板方法模式]] | - | 定义算法骨架，步骤延迟到子类 |
| [[访问者模式]] | - | 对对象结构定义新操作，不改变元素类 |

## 总结

23种经典设计模式形成了软件设计的模式宝库，通过合理的分类和选择，可以有效解决面向对象设计中的常见问题，提高代码的可复用性、可维护性和灵活性。
