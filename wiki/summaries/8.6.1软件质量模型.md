# 软件质量模型

## 概述

根据 GB/T 25000.10—2016 标准，软件质量定义为"在规定条件下使用时，软件产品满足明确或隐含要求的能力"。质量模型是定义的特征集以及它们之间的关系集，为规约质量需求以及评价质量提供了一个框架。

## 质量特性层级关系

在 ISO/IEC 25000系列标准中，产品质量分为：
- **质量特性** → **质量子特性** → **质量属性**

这种层次化分解提供了便利的产品质量分级。一个系统可测量的、与质量相关的属性被称为质量测度相关的质量属性。

## 使用质量模型

使用质量描述了产品对[[利益相关方]]造成的影响，由软件、硬件、运行环境的质量以及用户、任务和社会环境的特性决定。

使用质量模型包含 **5个特性**：
- **有效性**：完成任务的能力
- **效率**：使用资源的合理性
- **满意度**：用户满意程度（有用性、可信性、愉悦性、舒适性）
- **抗风险**：降低风险的能力（经济风险缓解性、健康和安全风险缓解性、环境风险缓解性）
- **周境覆盖**：适应不同使用环境的能力（周境完备性、灵活性）

## 产品质量模型

产品质量模型将系统/软件产品质量属性划分为 **8个特性**：

| 特性 | 主要子特性 |
|------|-----------|
| 功能性 | 功能完备性、功能正确性、功能适合性 |
| 性能效率 | 时间特性、资源利用性、容量 |
| 兼容性 | 共存性、互操作性 |
| 易用性 | 可辨识性、易学性、易操作性、用户差错防御性 |
| 可靠性 | 成熟性、可用性、容错性、易恢复性 |
| 信息安全性 | 保密性、完整性、抗抵赖性、可核查性、真实性 |
| 维护性 | 模块化、可重用性、易分析性、易修改性、易测试性 |
| 可移植性 | 适应性、易安装性、易替换性 |

## McCall质量模型

McCall质量模型从三个方面考查软件质量：
- **软件运行**：正确性、可靠性、效率
- **软件修改**：可维护性、灵活性、可测试性
- **软件转移**：可移植性、可重用性、互运行性

## 质量管理基础

根据 ISO 9000系列标准（现代质量管理的结晶），质量管理8项原则包括：
1. 以顾客为关注焦点
2. 领导作用
3. 全员参与
4. 过程方法
5. 管理的系统方法
6. 持续改进
7. 以事实为基础进行决策
8. 与供方互利的关系
