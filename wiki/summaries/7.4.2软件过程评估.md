# 软件过程评估

软件过程评估是根据过程模型或其他模型对组织的软件过程所进行的规范评估，旨在确定组织软件过程状态、明确改进优先级并获取支持。

## 主要评估模型

### 1. CMM模型

CMM的核心思想是通过基于模型的过程改进，使软件组织的软件过程向更高成熟度等级迈进。评估遵循6个步骤：

1. **成立评估小组** — 由经验丰富的专家组成，需接受CMM专门培训
2. **填写成熟度问卷表** — 参评单位代表填写并回答问题
3. **分析调查问卷** — 评估小组进行分析
4. **现场访问与文档审核** — 判断KPA实践活动是否达标
5. **撰写调查报告** — 指明软件过程的强项和弱项
6. **绘制KPA剖面图** — 显示目标达成情况并提交结论

### 2. Trillum模型

主要用于嵌入式软件开发和支持的能力评估模型，以CMM为基础，有以下特点：
- 架构建立在路线图基础上
- 同时适用于软件和硬件
- 强调以用户为关注的焦点
- 包括技术成熟度，主要面向通信产品

### 3. Bootstrap方法

参考ISO 9000-3和ESA PSS-05等标准，设计了17个详细的过程质量属性结构，改进了CMM的问卷表和成熟度计算方法。在欧洲有较大影响力。

### 4. ISO/IEC 15504标准

分为9个部分，核心是第二部分定义的二维参考模型：
- **过程维** — 软件开发各过程
- **能力维** — 6级过程性能：不完善→已实施→已计划与已跟踪→已建立→可预测→优化

### 5. SJ/T 11234-2001标准

我国行业标准，与CMMI连续式模型基本相同，包含22个过程域，分为四大类：

| 过程域分组 | 具体内容 |
|-----------|----------|
| 过程管理 | 组织级过程焦点、定义、培训、性能、改革与实施 |
| 项目管理 | 项目计划、监督控制、供方协议、集成管理、风险管理、定量管理 |
| 工程 | 需求管理、需求开发、技术解决方案、产品集成、验证、确认 |
| 支持 | 配置管理、度量和分析、质量保证、决策分析、因果分析 |


6个评估等级：不完整级→已执行级→受管理级→已定义级→定量管理级→持续优化级。
