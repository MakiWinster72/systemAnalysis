# 规范化理论

## 概述

规范化理论是数据库设计中的核心内容，旨在通过分解关系模式来消除数据冗余和各种操作异常，从而设计出性能优良的关系模式。

## 关系模式的异常问题

以关系模式 R(SNAME, CNAME, TNAME, TADDRESS) 为例分析存在的问题：

| 异常类型 | 描述 |
|---------|------|
| **数据冗余** | 某课程100名学生选修，任课教师信息重复100次 |
| **修改异常** | 修改教师地址需同时修改100个元组，易导致不一致 |
| **插入异常** | 不知学生名单时，无法录入教师任课情况和地址 |
| **删除异常** | 更换任课教师时，原教师地址信息会丢失 |

产生异常的根本原因在于属性之间的联系：学生与课程有直接联系，教师与课程有直接联系，但教师与学生之间无直接联系。

解决方案是将 R 分解为 R1(SNAME, CNAME) 和 R2(CNAME, TNAME, TADDRESS)。

## 函数依赖与键

### 函数依赖定义

设 R(U) 是属性集 U 上的关系模式，X 和 Y 是 U 的子集。若对于 R 的任意关系 r 中的任意两个元组 u、v，只要有 u[X] = v[X]，就有 u[Y] = v[Y]，则称 **X 函数决定 Y** 或 **Y 函数依赖于 X**，记作 X → Y。

### 函数依赖类型

| 类型 | 定义 |
|------|------|
| **完全函数依赖** | X → Y，且对于 X 的任何真子集 X'，X' → Y 不成立 |
| **部分函数依赖** | X → Y，但 Y 不完全函数依赖于 X |
| **传递函数依赖** | X → Y (Y 不是 X 的真子集)，且 Y → X 不成立，Y → Z |

### 键的概念

- **候选键**：X → U 在 R(U) 上成立，且不存在 X 的真子集 X' 使 X' → U 成立
- **主键**：在多个候选键中选择一个作为主键
- **外键**：两关系公共属性集，若在一关系中是主键，则为另一关系的外键

### 图示法求候选键

步骤：
1. 用有向图表示函数依赖关系（顶点为属性，弧为依赖）
2. 找出入度为 0 的属性集作为起点
3. 若能遍历所有顶点则为候选键；否则需加入中间顶点直至可遍历全部

## 范式

### 范式层级

```
5NF ⊂ 4NF ⊂ BCNF ⊂ 3NF ⊂ 2NF ⊂ 1NF
```

实际应用中一般达到 [[3NF]] 即可。

### 各范式定义

| 范式 | 定义 |
|------|------|
| **1NF** | 所有属性只包含原子值，即每个分量都是不可再分的数据项 |
| **2NF** | 满足 1NF，且每个非键属性完全依赖于候选键（无部分函数依赖） |
| **3NF** | 满足 2NF，且非键属性不传递依赖于候选键 |
| **BCNF** | 满足 1NF，且每个函数依赖的左部都必须包含候选键 |
| **4NF** | 满足 BCNF，且不存在非平凡的多值依赖 |

### 规范化示例

**2NF 示例**：选课关系 SC(Sno, Cno, Grade, Credit)
- 候选键：(Sno, Cno)
- 问题：Cno → Credit 是部分函数依赖
- 分解：SC1(Sno, Cno, Grade) 和 SC2(Cno, Credit)

**3NF 示例**：学生关系 S(Sno, Sname, Dno, Dname, Location)
- 函数依赖：Sno → (Sname, Dno, Dname, Location)，Dno → (Dname, Location)
- 问题：Sno → Dno → Dname（传递依赖）
- 分解：S1(Sno, Sname, Dno) 和 S2(Dno, Dname, Location)

**4NF 示例**：关系 QY(ypm, bm, sccj)
- 多值依赖：ypm →→ bm，ypm →→ sccj
- 分解：QY1(ypm, bm) 和 QY2(ypm, sccj)

## 关键概念总结

- [[函数依赖]] 是数据库约束的基础，决定关系模式所属范式
- [[候选键]] 求解是进行范式界定的关键技能
- 规范化通过模式分解消除异常，但可能引入查询连接操作
- 实际设计需要在规范化和查询效率之间平衡
