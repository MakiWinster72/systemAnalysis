# Web服务测试与嵌入式系统分析

## Web服务测试（16.5.6）

### 测试特性

Web服务测试与传统软件测试相比具有独特特性：

| 测试因素 | Web服务测试特征 |
|---------|---------------|
| 测试参与者 | 需要服务提供者、代理和请求者共同参与 |
| 测试分布 | 分布、远程、多阶段 |
| 测试模型 | 不拥有服务代码，可控制性和可观测性低 |
| 测试覆盖 | 除服务开发者外，其他参与者只有黑盒覆盖范围 |
| 测试执行 | 在线、及时测试 |
| 测试客户端 | 需要构建测试客户端调用被测服务 |
| 测试预测 | Web服务动态绑定，难以预测实际运行情况 |
| 回归测试 | 在线、基于运行时数据，除开发者和提供者外均不掌握服务演化情况 |

### 测试内容三个层次

1. **Web服务基础设施的验证与确认**：Web服务中间件稳定性和可靠性相对薄弱，XML技术灵活但协议可证明性存在挑战。SOAP RPC作为核心协议，其验证仍有待加强。

2. **[[嵌入式数据库系统]]独立测试**：保证各服务节点质量，包括：
   - 验证服务实现与描述的一致性
   - 服务代理对多个服务进行测试、比较和评估
   - 建立机制支持不同版本的跟踪及回归测试

3. **Web服务集成测试**：通过静态验证和动态模拟方法，确认服务描述能正确描述业务需求，能被服务中介正确解析，能由所有服务节点正确执行。

## 嵌入式系统概述（17.1）

### 嵌入式系统特点

- **专用性强**：针对具体应用专门设计，软硬件结合紧密，生命周期长
- **实时性强**：对外来事件在限定时间内及时响应
- **软硬件依赖性强**：必须协同设计以满足性能、成本和可靠性要求
- **专用处理器**：可靠性高、功耗低、体积小、集成度高
- **多种技术紧密结合**：计算机、半导体、电子、机械技术融合
- **系统透明性**：用户可能感知不到嵌入式系统存在
- **系统资源受限**：存储容量、I/O设备数量和处理器能力有限

### 系统组成

核心功能部件包括：传感器、处理单元(PE)、作动器、输入/输出接口。体系架构分为：
- 硬件层（微处理器、存储器、I/O接口）
- 中间层（硬件抽象层HAL/板级支持包BSP）
- 系统软件层（RTOS、文件系统、GUI、嵌入式数据库）
- 功能层（应用程序）

### 基于多核处理器的嵌入式系统

六种处理器体系结构：单核结构、多处理器结构、超线程结构(SMT)、多核结构、共享Cache的多核结构、采用超线程技术的多核结构。多核技术可降低系统功耗、体积和成本，但带来系统确定性方面的挑战。

### 安全攸关系统

也称安全关键系统，不正确功能或失效会导致人员伤亡或财产损失。常用可靠性/安全性设计模式：

- **TMR模式（三模块冗余）**：适用于无fail-safe状态的系统，提供3个并行运作通道，通过表决器采用少数服从多数原则
- **监控-启动器模式**：适用于有fail-safe状态的系统，额外增加传感器和监控器

## 嵌入式数据库系统（17.2）

### 基本特性

嵌入式数据库管理系统(EDBMS)需要具备：
- **嵌入性**：可嵌入软件或硬件设备
- **实时性**：第一时间获得系统资源并响应请求
- **移动性**：适应移动设备大规模应用
- **伸缩性**：适应千差万别的硬件和软件平台

### 分类

1. **嵌入式内存数据库管理系统**：处理离散、简单数据，将数据库主拷贝或工作版本驻留内存。典型产品：FineDB In-Memory、eXtremeDB、SolidDB

2. **嵌入式实时数据库管理系统**：处理连续实时数据流，保证数据操作在限定时间内完成。典型产品：eXtremeDB、Empress、RDM。适用于过程控制、电网监测、智能交通等系统

3. **移动数据库管理系统**：支持移动计算，处理远程数据副本。关键技术包括：数据库微型化、移动事务处理、数据缓存与同步、数据广播、移动查询处理。典型产品：小金灵(KingBase Lite)、OpenBASE Mini、SQLite、Berkeley DB

### 使用环境特点

- 设备随时移动性
- 网络频繁断接
- 网络条件多样化
- 通信能力不对称

### 系统组成

完整的EDBMS包括：
- 嵌入式数据库（功能独立的单用户DBMS）
- 同步服务器（连接枢纽，保证数据一致性）
- 数据库服务器（Oracle、Sybase等大型数据库）
- 连接网络（固定网络或无线网络）
