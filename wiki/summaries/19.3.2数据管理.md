# 19.3.2 数据管理

数据管理是大数据处理系统中必不可少的非功能模块，负责系统数据整体的稳定性和安全性，并提供监控指标反映系统功能情况。数据管理通常分为四个部分：元数据管理、数据关系图谱、数据安全和资源监控。

## 元数据管理

元数据是描述数据的数据，为系统各类数据提供上下文环境。元数据分为技术元数据和业务元数据两类：

- **技术元数据**：存储数据仓库系统技术细节，有助于明确数据存储结构、厘清数据关系、提升开发效率，支持数据血缘追溯和影响分析
- **业务元数据**：描述数据业务含义和业务规则，为数据应用提供更好的服务

元数据管理包括七种方式：数据源元数据、ETL规则元数据、数据仓库元数据、报表元数据、接口文件格式元数据、商业元数据和其他元数据（访问日志、装载日志）。

## 数据关系图谱

数据关系图谱记录数据间的关联关系和血缘关系，支持快速获取数据关系，高效分析数据价值。

**血缘关系四个基本特征**：
1. **归属性**：数据归属于特定组织或个人
2. **多源性**：同一数据可有多个来源
3. **可追溯性**：体现数据从产生到消亡的完整生命周期
4. **层次性**：不同描述信息形成数据层次结构

[[数据血缘关系]]在数据溯源过程中找到相关数据间的联系，通过血缘分析实现数据融合处理的可追溯性。

## 数据安全

数据安全公式：**数据安全 = 认证 + 授权**

- **认证**：用户身份确认（如Kerberos认证框架）
- **授权**：用户可访问的资源（如RBAC、Apache Sentry/Ranger）

**数据安全流程**：数据产生→数据存储→数据使用→数据传输→数据展示→数据销毁

**表安全等级**：S1（业务核心表，影响其他部门）、S2（业务核心表，本部门使用）、S3（非业务核心表，有一定影响）、S4（非业务核心表，无影响）

## 资源监控

大数据监控围绕海量全网数据，借助监测系统协助分析。监控维度包括：

| 监控维度 | 主要监控项 |
|---------|-----------|
| 底层基础监控 | 机房与网络、服务器（CPU、内存、IO、磁盘） |
| 服务状态监控 | 组件存活状态（HDFS、Hive、ZK等） |
| 组件性能监控 | Metrics性能监控 |
| Runtime监控 | 模拟客户端基本请求与操作 |
| 集群指标监控 | 文件分布、计算/存储资源 |
| 任务状态监控 | 任务状态、资源占用、延迟 |
| 趋势预测监控 | 存储计算趋势、SLA趋势 |

## 核心关联

[[数据血缘关系]]是数据治理的关键概念，确保数据质量需要每个处理环节都进行质量检测。[[数据安全]]体系通过认证和授权机制保护数据资产，配合数据分级和加密措施实现全生命周期安全。
