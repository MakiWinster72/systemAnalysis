# 单调速率调度算法（Rate Monotonic Scheduling）

## 定义

单调速率调度算法（Rate Monotonic Scheduling, RMS）是实时系统中一种经典的**静态固定优先级调度算法**。该算法的核心原则是：任务的优先级与执行周期呈单调函数关系，**执行越频繁的任务优先级越高**，即周期越短，优先级越高。

RMS 由 Liu 和 Layland 于 1973 年提出，是静态调度算法中最有效的算法。理论上证明：**如果一组任务能够被任何一种静态调度算法所调度，那么在 RMS 算法下一定是可调度的**。

## 算法假设

RMS 算法基于以下六项假设：

1. **周期性任务**：所有任务都是周期性的
2. **任务独立性**：任务间不需要同步，没有共享资源，没有数据交换
3. **抢占式调度**：系统总是执行优先级最高且就绪的任务
4. **即时截止时间**：任务的时限是其下一周期的开始
5. **定常执行时间**：每个任务具有不随时间变化的固定执行时间
6. **同等关键性**：所有任务具有同等重要的关键性级别

## RMS 定理

对于具有 n 个任务的实时系统，所有任务满足硬实时条件的**充分条件**为：

```
Σ(Ei/Ti) < n(2^(1/n) - 1)
```

其中：
- **Ei**：任务 i 的最长执行时间
- **Ti**：任务 i 的执行周期
- **Ei/Ti**：任务 i 所需的 CPU 利用率

### CPU 利用率上限

当任务数量 n 趋于无穷大时，该上限趋近于 **69.3%**（约 70%）。

| 任务数 n | 利用率上限 |
|---------|-----------|
| 1 | 100% |
| 2 | 82.8% |
| 3 | 78.0% |
| 4 | 75.7% |
| ∞ | 69.3% |

**工程实践原则**：作为实时系统设计的一般准则，CPU 利用率应控制在 **60% ~ 70%** 之间，以确保系统有足够的容错空间。

## 可调度性分析方法

[[concepts/实时系统可调度性分析|RMA 分析法]]（Rate Monotonic Analysis）基于 RMS 定理，通过以下步骤判断系统可调度性：

1. **计算各任务 CPU 利用率**：Ei/Ti
2. **求和总利用率**：Σ(Ei/Ti)
3. **比较理论上限**：n(2^(1/n) - 1)
4. **判断结论**：若总利用率 < 理论上限，则系统可调度

### 应用示例

| 周期性任务 | 执行时间 (ms) | 周期 (ms) | CPU 利用率 |
|-----------|--------------|----------|-----------|
| 任务1 | 20 | 100 | 20% |
| 任务2 | 25 | 150 | 16.7% |
| 任务3 | 50 | 300 | 16.7% |
| **总计** | — | — | **53.3%** |

该系统 n=3，理论上限为 78.0%，实际利用率 53.3% < 78.0%，故系统可调度。

## 与其他调度算法比较

| 特性 | RMS | [[concepts/EDF调度算法|EDF]] |
|------|-----|-----------|
| 优先级类型 | 静态固定 | 动态变化 |
| CPU 利用率上限 | ~70% | 100% |
| 实现复杂度 | 较低 | 较高 |
| 可预测性 | 好 | 较差 |

## 应用场景

RMS 适用于：
- 任务特性已知且相对稳定的[[concepts/实时系统]]
- 对可预测性要求高的硬实时系统
- 资源受限的嵌入式系统

## 优缺点

**优点**：
- 算法简单，易于实现
- 可预测性强
- 在静态算法中效率最高

**缺点**：
- CPU 利用率上限相对较低（~70%）
- 假设条件较为理想化
- 无法适应任务特性的动态变化
