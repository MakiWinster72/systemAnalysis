# 能力成熟度模型集成（CMMI）

## 概述

能力成熟度模型集成（Capability Maturity Model Integration，CMMI）是由美国卡内基梅隆大学软件工程研究中心（SEI）提出的软件过程改进框架。CMMI融合了多种成熟度模型，形成了组织范围内过程改进的单一集成模型，其主要目的是消除不同模型之间的不一致和重复，降低基于模型进行改进的成本。

软件过程评估是根据过程模型或其他模型对组织的软件过程所进行的规范评估，旨在确定组织软件过程状态、明确改进优先级并获取支持。CMMI正是这一评估过程的核心框架之一。

## 核心目标

- **统一集成**：整合多种成熟度模型，避免重复和冲突
- **成本优化**：降低基于模型进行过程改进的成本
- **组织改进**：帮助软件组织建立系统化的过程改进机制

## 表示法


CMMI继承并发展了两种表示法，这两种方法在逻辑上是等价的，对同一组织进行评估应得到相同的结论。

### 阶段式模型

阶段式模型沿袭了[[CMM软件能力成熟度模型]]的框架，仍保持5个成熟度等级：

| 成熟度等级 | 关键过程域 |
|------------|------------|
| **可重复级** | 需求管理、项目计划、配置管理、项目监督与控制、供应商合同管理、度量和分析、过程和产品质量保证 |
| **已定义级** | 需求开发、技术解决方案、产品集成、验证、确认、组织级过程焦点、组织级过程定义、组织级培训、集成项目管理、风险管理、集成化的团队、决策分析和解决方案、组织级集成环境 |
| **可管理级** | 组织级过程性能、定量项目管理 |
| **优化级** | 组织级改革与实施、因果分析和解决方案 |

> 当组织通过了某一等级过程域中的全部过程，即意味着该组织的成熟度达到了这一等级。利用阶段式模型对组织进行成熟度度量，概念清晰、易于理解、便于操作。

### 连续式模型

连续式模型将24个过程域按照功能划分为4个过程组：

| 过程组 | 过程域 |
|--------|--------|
| **过程管理** | 组织级过程焦点、组织级过程定义、组织级培训、组织级过程性能、组织级改革与实施 |
| **项目管理** | 项目计划、项目监督与控制、供应商合同管理、集成项目管理、风险管理、集成化的团队、定量项目管理 |
| **工程** | 需求管理、需求开发、技术解决方案、产品集成、验证、确认 |
| **支持** | 配置管理、度量和分析、过程和产品质量保证、决策分析和解决方案、组织级集成环境、因果分析和解决方案 |

连续式模型的特点：
- 每个过程域代表组织某一方面的能力
- 每个过程域的能力均分为5级
- 允许组织对过程域进行裁剪
- 允许对不同过程域采用不同能力等级
- 评估结果用**能力特征图**表示

## 相关评估标准

CMMI作为核心框架，与其他软件过程评估标准共同构成完整的评估体系：

### ISO/IEC 15504标准

国际标准化组织发布的[[ISO/IEC 15504软件过程评估标准]]，定义了用于过程评估的二维参考模型：
- **过程维**：软件开发各过程
- **能力维**：6级过程性能（不完善的过程→已实施的过程→已计划与已跟踪的过程→已建立的过程→可预测的过程→优化的过程）

该标准分为9个部分，其中过程与过程能力的参考模型详细定义了能力等级，并针对每个过程定义了具体的性能属性。

### SJ/T 11234-2001标准

我国行业标准《软件过程能力评估模型》针对软件组织对自身软件过程能力进行内部改进的需要，与CMMI连续式模型基本相同。该标准包含22个过程域，分为四大类：

| 过程域分组 | 具体内容 |
|-----------|----------|
| **过程管理** | 组织级过程焦点、组织级过程定义、组织级培训、组织级过程性能、组织级改革与实施 |
| **项目管理** | 项目计划、项目监督与控制、供方协议管理、集成项目管理、风险管理、定量项目管理 |
| **工程** | 需求管理、需求开发、技术解决方案、产品集成、验证、确认 |
| **支持** | 配置管理、度量和分析、过程和产品质量保证、决策分析和解决方案、因果分析和解决方案 |

该标准的6个评估等级与CMMI连续式模型相对应：不完整级→已执行级→受管理级→已定义级→定量管理级→持续优化级。

## 评估方法

基于CMM/CMMI的评估通常遵循以下步骤：

1. **成立评估小组** — 由软件工程和管理工作经验丰富的专家组成，小组成员应接受过CMM/CMMI基本概念和评估方法的专门培训
2. **填写成熟度问卷表** — 参评单位的代表认真填写并回答有关问题
3. **分析调查问卷** — 评估小组进行系统分析
4. **现场访问与文档审核** — 召开座谈会、审核过程文档，判断关键实践领域（KPA）的实践活动是否达到预定目标
5. **撰写调查报告** — 指明软件过程的强项和弱项
6. **绘制剖面图** — 显示是否达到目标并向有关部门提交评估的结论性意见

## 与CMM的关系


CMMI与CMM的关系：

- CMMI继承了CMM的核心思想
- CMMI融合了多种模型，消除了不一致和重复
- CMMI增加了更多的过程域（18个 vs 24个）
- 两者评价结论应该基本一致

## 实践意义

CMMI是提高软件组织成熟度和软件过程能力的有效工具：

> 组织无论采用CMM模型还是采用CMMI模型，无论是使用阶段式模型还是连续式模型，都能提高软件过程的成熟度和项目过程能力。

其他相关评估模型还包括：
- **Trillum模型** — 主要用于嵌入式软件开发，架构建立在路线图基础上，同时适用于软件和硬件，强调以用户为关注的焦点
- **Bootstrap方法** — 参考ISO 9000-3和ESA PSS-05等标准，设计了17个详细的过程质量属性结构，在欧洲有较大影响力
