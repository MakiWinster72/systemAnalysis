# 容灾技术

容灾技术是指在各种灾难发生的情况下，保证信息系统业务连续性的技术体系。容灾系统的实现可以采用不同的技术，例如既可以采用硬件进行远程数据复制，也可以采用软件实现远程的实时数据复制，并且实现远程监控和切换。

## 业务持续性规划（BCP）

业务持续性规划（Business Continuity Planning，BCP）是在非计划的业务中断情况下，使业务继续或恢复其关键功能的一系列预定义的过程。BCP帮助企业确认影响业务发展的关键性因素及其可能面临的威胁，拟定计划与步骤确保关键因素在任何状况下都能正常持续发挥。BCP的目标是**确定并减少风险可能带来的损失，有效地保障业务的连续性**。

### BCP实施阶段

企业推动BCP需要经过8个主要阶段：
1. **项目启动**
2. **风险评估与消减**
3. **业务影响分析**
4. **业务持续性策略**
5. **开发BCP**
6. **人员培训与训练**
7. **测试与演练**
8. **BCP的持续维护及变更管理**

### BCP主体框架

企业范围内的BCP流程主体框架主要由4个部分组成：

| 组成部分 | 说明 |
|---------|------|
| **灾难恢复规划（DRP）** | 关注信息系统的恢复，重点是技术层面的恢复流程 |
| **业务恢复规划（BRP）** | 关注业务功能的恢复，确保关键业务能够重新运行 |
| **危机管理规划（CMP）** | 处理灾难期间的决策和沟通管理 |
| **持续可用性（CA）** | 通过高可用技术实现业务的不间断运行 |

### BCP平衡计分卡

为衡量BCP流程，可使用BCP平衡计分卡进行评估：
- **价值综述**：明确BCP创造的 business value
- **价值计划**：规划BCP的投入与产出
- **BCP风险度量标准**：量化评估风险水平
- **执行协议**：确保BCP措施得到落实
- **有效方法**：持续改进BCP流程

在平衡计分卡中，企业需要确定BCP流程的远景目标，并与企业管理和基础设施发展相协调。关键成功因素包括：增长及改革、顾客满意度、员工情况、流程质量、财政情况。

## 容灾能力等级

根据国家相关规范，容灾能力可分为6个等级，高等级涵盖低等级功能：

| 等级 | 名称 | 说明 |
|------|------|------|
| 第1级 | 基本支持 | 提供基本的数据备份能力 |
| 第2级 | 备用场地支持 | 提供备用场地用于恢复 |
| 第3级 | 电子传输和部分设备支持 | 电子传输配合部分备用设备 |
| 第4级 | 电子传输及完整设备支持 | 完整的备用硬件设施 |
| 第5级 | 实时数据传输及完整设备支持 | 实时同步与完整备用系统 |
| 第6级 | 数据零丢失和远程集群支持 | 零数据丢失，实现远程集群 |

## 容灾技术分类

### 数据容灾

数据容灾的关注点在于数据，即灾难发生后可以确保用户原有的数据不会丢失或遭到破坏。数据容灾较为基础，其中：

- **较低级别方案**：利用磁带库和管理软件实现数据异地备份
- **较高级别方案**：依靠数据复制工具（如卷复制软件或存储系统硬件控制器）实现数据远程复制

数据容灾是保障数据可用的最后底线。当数据丢失时能够保证应用系统可以重新得到所有数据。从这种意义上说，数据备份属于数据容灾的范畴。这种方案花费较低，构建简单，但灾难恢复时间较长，灾难发生时应用会被中断，用户业务将被迫停止。

### 应用容灾

应用容灾是在数据容灾的基础上，再将执行应用处理能力复制一份，在备份站点同样构建一套应用系统。应用容灾系统能提供不间断的应用服务，让用户应用的服务请求能够透明地继续运行，感受不到灾难发生，保证信息系统提供的服务完整、可靠和安全。

应用容灾需要通过更多软件来实现，它可以使企业的多种应用在灾难发生时进行快速切换，确保业务的连续性。对于业务应用繁多并且系统需要保持7×24小时连续运行的企业，需要高级别的应用容灾来满足需求。

## 容灾恢复规划

容灾技术的实施需要结合[[灾难恢复规划]]，形成一个周而复始、持续改进的过程。灾难恢复规划与BCP相互配合，共同构成完整的业务连续性保障体系。

### 1. 灾难恢复需求确定

- **风险分析**：标识信息系统资产价值，识别面临的自然和人为威胁，分析脆弱性，定量或定性描述可能造成的损失
- **业务影响评估**：分析业务功能及资源配置，明确信息保密性、完整性和可用性要求，评估中断影响
- **确定灾难恢复目标**：明确关键业务功能及恢复优先顺序，确定 [[RTO]] 和 [[RPO]] 的范围

### 2. 灾难恢复策略制定

支持灾难恢复的资源包括7个要素：
- 数据备份系统
- 备用数据处理系统
- 备用网络系统
- 备用基础设施
- 技术支持能力
- 运行维护管理能力
- 灾难恢复预案

策略制定原则：在灾难恢复资源成本与风险损失之间取得平衡，不同业务功能可采用不同的灾难恢复策略。

### 3. 灾难恢复策略实现

- **灾难备份系统技术方案实现**：包含数据备份系统、备用数据处理系统和备用网络系统
- **灾难备份中心选择和建设**：避免与主中心同时遭受同类风险，具备便捷交通和通信电力资源
- **技术支持能力实现**：建立技术支持组织，定期培训技术人员
- **运行维护管理能力实现**：建立操作管理制度，保证备份及时有效
- **灾难恢复预案实现**：按 GB/T 20988—2007 要求制定并落实

### 4. 灾难恢复预案管理

灾难恢复预案的完整生命周期管理包括：

1. **起草**：参照GB/T 20988—2007附录B的灾难恢复预案框架，按照风险分析和业务影响分析所确定的灾难恢复内容进行撰写
2. **评审**：对预案初稿的完整性、易用性、明确性、有效性和兼容性进行严格评审
3. **测试**：包含基本单元测试、关联测试和整体测试，形成测试报告
4. **修订**：根据评审和测试结果纠正问题，形成报批稿
5. **审核和批准**：由灾难恢复领导小组进行审核和批准，确定为执行稿

为了使相关人员了解信息系统灾难恢复的目标和流程，熟悉灾难恢复的操作规程，企业应组织灾难恢复预案的教育、培训和演练。
