# BSP企业系统规划法

**BSP（Business System Planning，企业系统规划）**是由IBM公司于20世纪70年代提出的一种信息系统规划方法，主要用于大型信息系统的开发。BSP是[[战略数据规划法]]（SDP）和[[信息工程法]]（IE）的基础，理解BSP对于全面掌握信息系统开发方法具有重要帮助。

## 核心原则

BSP方法遵循以下五项基本原则：

1. **支持企业战略目标**：BSP可看作一个转化过程，把企业的战略目标转化为信息系统的战略目标
2. **表达各管理层次需求**：信息系统应满足战略计划层、管理控制层和操作控制层三个层次的需求
3. **提供一致信息**：把数据作为企业资源加以确定和统一规划管理，确保数据一致性
4. **适应组织变化**：采用企业发展过程的概念，使技术独立于企业组织结构
5. **自上而下规划、分步实现**：对大型信息系统采取自上而下的系统规划，自下而上分步实现

## 基本步骤

BSP方法通过全面调查分析企业信息需求，制定信息系统总体方案。其活动步骤可归纳为四个基本步骤：

1. **定义管理目标**：确定企业的管理目标体系
2. **定义管理功能**：识别企业核心业务功能
3. **定义数据分类**：将相关数据按逻辑归类
4. **定义信息结构**：建立信息系统的总体结构

完整的BSP过程包含13个步骤，从准备工作开始，经过定义企业过程、定义数据类、分析现有系统、确定管理部门要求、提出判断和结论，到定义信息总体结构、确定优先顺序、评价信息资源管理，最后制订建议书和开发计划，完成成果报告。

## 前期准备工作

BSP被形象地称为**"一把手工程"**，必须获得最高领导者的参与承诺。具体准备工作包括：

- **成立系统规划组（SPG）**：选择SPG组长，由一位企业领导全职参加
- **收集数据**：包括企业一般情况、现有系统情况，涉及计划数据、组织结构数据、业务活动数据、环境数据和技术数据
- **制订计划**：画出PERT图和甘特图，准备调查表和调查提纲
- **开好介绍会**：由最高层领导主持，全体SPG成员和相关部门负责人出席

## 核心矩阵工具

BSP方法使用三种核心矩阵工具来辅助分析和规划：

### PO矩阵（过程/组织矩阵）
**Process/Organization矩阵**把企业组织结构与企业过程联系起来，说明每个过程与组织的联系及其决策人。

| 符号 | 含义 |
|------|------|
| √ | 负责和决策 |
| ⊥ | 过程主要涉及 |
| + | 过程有涉及 |
| 空白 | 过程不涉及 |

### RD矩阵（资源/数据矩阵）
**Resource/Data矩阵**列出企业资源与数据类型的对应关系，识别存档数据、事务数据、计划数据和统计数据四类数据。

### CU矩阵（Create/Use矩阵）
以企业过程为行、数据类为列，填写C（Create，创建）和U（User，使用）来表达过程与数据类的联系。通过功能组合和数据类调整后，CU矩阵可形成各个子系统。

## 企业过程定义

企业过程是**企业资源管理所需要的、逻辑相关的一组决策和活动**，定义企业过程主要涉及三类资源：

1. **战略计划与管理控制过程**：包括长远计划或发展规划，操作计划、管理计划和资源计划
2. **产品/服务过程**：按产品/服务生命周期（产生阶段、获得阶段、服务阶段、归宿阶段）识别
3. **支持性资源过程**：包括材料、资金、设备和人员四类基本支持性资源

BSP方法认为正常情况下一般有4～12个过程组，便于规划的过程最大数量是60个。

## 优先顺序确定

系统逻辑优先顺序主要依据四个方面的因素：

- 需求
- 对企业的影响
- 潜在的利益分析
- 成功的可能性

将每个方面划分成1～10个等级，绘制图形以便强调最迫切需求的子系统。

## 与其他方法的关系

BSP方法在实践中常与[[关键成功因素法]]（CSF）和[[战略集合转化法]]（SST）结合使用，形成**CSB方法**：先用CSF确定企业目标，用SST补充完善并转化为信息系统目标，最后用BSP校核目标并确定信息系统结构。

BSP的真正价值在于创造一种环境和提出初步的行动计划，使企业能够积极响应系统和优先次序的变化，避免重大设计失误。
