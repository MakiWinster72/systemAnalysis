# 对象关系映射（ORM）

## 定义

对象关系映射（Object/Relation Mapping, ORM）是一种将内存中的对象与关系数据库中的关系数据进行相互转换的技术。由于对象和关系数据是业务实体的两种不同表现形式——对象存在于内存中，关系数据存在于数据库的二维表格中——两者之间的差异（称为"阻抗失配"）需要通过ORM技术来弥合。

关系模型由**关系数据结构**、**关系操作集合**和**关系完整性规则**三部分组成，由IBM公司的E.F.Codd系统提出。关系数据库中涉及的基本术语包括：

| 术语 | 说明 |
|-----|------|
| 属性（Attribute） | 描述实体的特征，如学号、姓名、性别等 |
| 域（Domain） | 属性的取值范围，必须是原子数据（Atomic Data） |
| 目或度（Degree） | 二维表关系的列数 |
| 候选码（Candidate Key） | 唯一标识元组的属性或属性组 |
| 主码（Primary Key） | 选定的候选码 |
| 外码（Foreign Key） | 引用其他关系主码的属性 |

## 核心问题：阻抗失配

### 对象模型 vs 关系模型

| 对象模型特征 | 关系模型限制 |
|------------|-------------|
| 支持继承和多态 | 二维表格无法直接表达继承关系 |
| 支持多对多关联 | 需要通过中间表间接实现 |
| 方法和封装特性 | 仅表示数据，无行为 |
| 基于引用和指针 | 基于外键和集合论 |
| 身份由内存地址确定 | 身份由主码（Primary Key）确定 |

### 阻抗失配的具体表现

1. **粒度不匹配**：对象可以包含复合类型，关系表需扁平化
2. **类型不匹配**：对象有引用类型，数据库需外键关联
3. **关联不匹配**：对象的多对多关联在数据库中需要中间表
4. **继承不匹配**：对象的继承层次无法直接映射到表结构
5. **标识不匹配**：对象的OID（对象标识）与关系的主码（Primary Key）机制不同
6. **操作不匹配**：对象支持导航访问，关系需要SQL查询

### 理论根源

阻抗失配的本质在于理论基础不同：
- **对象模型**：基于面向对象理论，强调封装、继承、多态
- **关系模型**：基于数学集合论和谓词逻辑，强调数据的数学特性

1962年CODASYL发表的"信息代数"首次将数学方法用于数据处理，1968年David Child实现了集合论数据结构，而E.F.Codd在IBM公司系统提出了关系模型，奠定了现代[[关系数据库]]的理论基础。

## ORM的核心功能

根据 [[summaries/13.4.2对象持久化与数据库]]，ORM主要实现以下功能：

- **对象持久化**：将内存中的对象保存到关系数据库
- **数据加载**：从数据库读取关系数据并重新组装为对象
- **映射管理**：自动维护对象属性与数据库字段的对应关系
- **查询语言**：提供面向对象的查询方式（如HQL）来替代原生SQL
- **完整性约束**：维护[[外码]]（Foreign Key）等参照完整性规则

## 主流ORM框架

### Hibernate

Hibernate是当前最流行的开源对象关系映射框架之一，对JDBC进行了非常轻量级的对象封装，使Java程序员可以使用对象编程思维来操作数据库。

Hibernate的核心特性包括：

- **HQL查询语言**：Hibernate查询语言（HQL）被设计成SQL的一个轻量级面向对象扩展，是对象和关系之间的桥梁
- **多查询方式支持**：除了HQL，Hibernate还支持用原生SQL或基于Java的标准和示例查询（Example Query）表达查询
- **XML映射文件**：使用XML文件（.hbm.xml）把Java类映射到数据库表，把JavaBean属性映射到表的列
- **数据库无关性**：通过JDBC技术，支持所有的SQL数据库管理系统，开发者只需修改配置即可切换数据库

Hibernate是 [[summaries/16.3.3 .NET开发框架]] 中介绍的SSH轻量级架构中的核心持久层组件，体现了"数据库无关性"的架构优势。

### 其他框架

- **iBatis/MyBatis**：半自动框架，支持原生SQL控制，灵活性较高
- **EclipseLink**：开源ORM实现
- **Spring Data JPA**：基于JPA规范的简化实现

## ORM在SSH架构中的角色

在 [[summaries/16.3.2 Java EE开发框架]] 介绍的SSH（Spring、Struts、Hibernate）轻量级架构中，Hibernate作为ORM框架承担数据持久层的职责：

- **DAO层实现**：Hibernate封装了数据库访问逻辑，提供DAO组件
- **配置管理**：通过XML映射文件配置Java类与数据库表的对应关系
- **会话管理**：与Spring框架集成，由Spring管理SessionFactory的生命周期

SSH架构的典型分层为：视图层（JSP/浏览器）→ 控制层（Struts）→ 业务层（Spring Service）→ **持久层（Hibernate DAO）** → 数据库

## ORM与CMP的区别

[[summaries/13.4.2对象持久化与数据库]] 还介绍了CMP（容器管理持久化）技术：

- **CMP**：由EJB容器管理实体EJB的持久化，必须遵守J2EE规范
- **ORM**：负责持久化普通的Java对象（POJO），灵活性更高
- 两者都提供对象/关系映射服务，区别在于管理的实体类型和运行环境要求

## ORM的优势

- **开发效率**：减少样板代码，自动生成CRUD操作
- **数据库无关性**：通过配置切换不同数据库，Hibernate正是这一特性的典型代表
- **面向对象查询**：HQL等查询语言支持面向对象的关联查询和导航
- **对象导航**：支持面向对象的关联查询
- **缓存支持**：通常内置一级、二级缓存机制
- **企业级支持**：在SSH等成熟架构中与[[Spring框架]]、[[Struts框架]]等框架无缝集成
