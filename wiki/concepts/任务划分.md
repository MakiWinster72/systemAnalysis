# 嵌入式软件任务划分方法

## 概念定义

嵌入式软件任务划分是指根据应用的实时性要求、应用场合、可用资源情况等诸多约束，将嵌入式系统软件功能合理分配为独立任务的过程。这一过程直接影响嵌入式软件设计的质量，是[[嵌入式软件设计]]中的核心环节。

## 任务划分步骤

根据[[summaries/17.4.4系统分析与设计]]的指导，任务划分分为三个主要步骤：

### 步骤一：明确实时性指标

首先需要明确系统的**实时性要求**：
- 区分**软实时**与**硬实时**
- 确定最坏情况下的实时时限
- 确定任务的大体数目

任务划分的力度和数目合理性直接影响：
- 调度开销
- 任务间通信开销
- 系统响应时间

> **关键原则**：实时系统的软件应尽可能简化，过于复杂的软件设计会增加系统复杂性，从而降低可靠性。

### 步骤二：可调度性分析

对已划分任务进行系统分析：

1. **任务分类**：根据功能特点对任务进行分类
2. **识别关键任务**：识别具有**硬实时性要求**的所有关键任务
3. **优先级分配**：为所有任务赋予适当的任务优先级
4. **粗略分析**：根据执行时间估计值，在考虑调度开销余量的条件下进行可调度性分析

#### 任务合并与重组策略

根据分析结果对任务进行适当调整：

| 合并策略 | 目的 |
|---------|------|
| 周期相同的任务合并 | 降低事件分发机制的开销 |
| 固定顺序执行的任务合并 | 避免同步开销 |
| 相同事件源触发的任务合并 | 减小事件分发机制的开销 |
| 计算密集型/数据处理功能独立 | 由单一优先级任务实现 |

> **注意**：需对任务间的同步与互斥机制进行分析，**尽量避免大粒度的互斥锁**。

### 步骤三：优先级分配

在具体实现时，根据系统特点确定任务优先级。任务优先级分配的一般原则如下：

#### 1. 中断关联性原则

与中断服务程序(ISR)相关联的任务应安排**尽量高的优先级**，以保证及时处理异步事件，提高系统的实时响应能力。

**原因**：若优先级不足，CPU可能被其他高优先级任务长期占用，导致第二次中断发生时上一次中断还未处理，从而产生信号丢失甚至外部设备失败。

#### 2. 紧迫性原则

越紧迫的任务对响应时间的要求越严格。应根据紧迫任务的响应时间先后顺序安排优先级。

#### 3. 任务频繁性原则

对于周期性任务：
- 执行越频繁 → 周期越短 → 允许耽搁时间越短 → **优先级应越高**
- 处理时间越短 → **优先级也应越高**

#### 4. 传递性原则

信息处理流程中，**前驱任务的优先级应高于后继任务**。

**典型示例**：数据采集任务的优先级应高于数据处理任务的优先级。

## 核心要点总结

嵌入式软件任务划分的核心是**在系统复杂性与可靠性之间取得平衡**，通过合理的任务粒度控制和优先级分配，确保系统在满足实时性约束的前提下保持良好的可维护性和可扩展性。
