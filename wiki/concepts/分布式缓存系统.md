# 分布式缓存系统：Memcache、Redis、Tair的实现原理与分布式算法

分布式缓存系统是指缓存数据分布在不同的服务器上，通过缓存技术实现数据的快速访问和高并发的请求处理。

## 基本原理

分布式缓存的典型应用场景包括：
- 缓存经过复杂计算得到的数据
- 缓存系统中频繁访问的热点数据
- 减轻数据库压力，提升系统响应速度

---

## Memcache

### 实现原理

Memcache通过在内存里维护一个统一且巨大的[[哈希表]]（Hash Table）来提高读取速度，能够存储各种格式的数据，包括图像、视频、文件以及数据库检索结果等。

### 核心特性

| 特性 | 说明 |
|------|------|
| **存储方式** | 使用物理内存作为缓存区，键值（key/value）方式存储 |
| **进程限制** | 每个进程最大2GB |
| **持久化** | 不支持，重启服务会导致数据丢失 |
| **服务器通信** | 服务器之间彼此不通信，分布式能力依赖客户端实现 |

### 缓存淘汰策略

Memcache采用[[LRU缓存淘汰策略]]（Least Recently Used）。当服务器用完分配的内存时：
1. 失效的数据被首先替换
2. 其次是最近未使用的数据

同时使用**Lazy Expiration**策略：不会监控存入的键/值对是否过期，而是在获取key值时查看时间戳，以减轻服务器负载。

---

## Redis

### 实现原理

Redis是一个开源的高性能键值对存储系统，支持多种数据结构，包括字符串、哈希、列表、集合和有序集合等。

Redis的分布式缓存技术使用[[一致性哈希]]算法，将缓存分散在多个节点上，每个节点存储部分缓存数据。

### 核心特性

| 优点 | 说明 |
|------|------|
| 高性能读写 | 单线程读写性能极高 |
| 多数据类型支持 | 支持字符串、哈希、列表、集合、有序集合 |
| 数据持久化 | 支持RDB和AOF两种持久化方式 |
| 高可用架构 | 支持主从复制、哨兵模式、集群模式 |
| 分布式分片集群 | 支持水平扩展 |

### 与Memcache对比

Redis支持多线程读写（但单线程性能更高），而Memcache在纯多线程场景下性能更优。

---

## Tair

Tair是淘宝开发的分布式缓存系统，同样采用[[一致性哈希]]或类似分布式算法实现数据分片，具有高可用和可扩展的特点。

---

## 分布式缓存算法

### 1. 哈希取余算法

通过公式计算数据映射到的节点：

```
节点 = Hash(key) % N
```

其中N为节点总数。

**缺点**：当节点数量变化时，大多数数据映射位置都会改变，导致缓存大量失效。

### 2. 一致性哈希算法

将所有存储节点排列在首尾相接的[[Hash环]]上：
1. 每个key计算出Hash值后，按照顺时针方向找到邻接的存储节点存放
2. 当有节点加入或退出时，仅影响该节点在Hash环上顺时针方向相邻的后续节点

**优点**：减少节点变动对整体系统的影响，提高缓存命中率。

### 3. 虚拟Hash槽算法

使用散列性能良好的哈希函数把所有数据映射到一个固定范围的整数集合中：

- 整数定义为**槽**（slot），范围远大于节点数
- 槽是集群内数据管理和迁移的基本单位
- 每个节点负责一定数量的槽

**优点**：方便数据拆分和集群扩展，Redis Cluster采用此算法。
