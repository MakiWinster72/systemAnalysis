# 数据ETL过程与架构

## 定义

**ETL**（Extract-Transform-Load）是数据集成领域的核心概念，代表**抽取（Extract）、转换（Transform）、加载（Load）**三个阶段的统称。它是从多个数据源提取数据，进行清洗和转换，最终加载到[[数据仓库]]或其他目标系统的过程。

在[[summaries/19.3.1数据存储]]中，ETL被描述为大数据处理系统数据存储流程的关键组成部分，与数据采集、数据清洗、数据转换、数据存储共同构成了完整的数据处理链路。从数据仓库的角度看，ETL负责将分布的、异构数据源中的数据（如关系数据、平面数据文件等）抽取到临时中间层后进行清洗、转换和集成，最后加载到数据仓库或[[数据集市]]中，成为[[OLAP]]和[[数据挖掘]]的基础。

---

## ETL的三个核心阶段

### 1. 抽取（Extract）
从各种异构数据源中提取原始数据，包括：
- 关系型数据库
- 日志文件
- Web服务器日志
- API接口数据
- 外部第三方数据
- **分布式数据库中的数据片段**：根据[[数据分片]]策略，从不同物理节点抽取水平分片或垂直分片的数据

### 2. 转换（Transform）
对抽取的原始数据进行处理和转换：
- **数据清洗**：去除重复数据、纠正错误
- **格式转换**：统一数据类型和编码格式
- **数据规范化**：标准化字段值、单位
- **数据替换**：处理空值、默认值
- **属性分离**：从复合字段中提取多个属性
- **数据合并/拆分**：整合或分解数据记录

### 3. 加载（Load）
将转换后的干净数据写入目标系统：
- [[数据仓库]]
- [[数据湖]]
- 分析型数据库
- [[数据集市]]

## ETL技术要点

### 核心处理环节

根据[[summaries/5.6.2数据仓库概述]]，在技术上，ETL主要涉及以下五个核心环节：

| 环节 | 说明 |
|------|------|
| **关联（Association）** | 处理多数据源之间的关联关系 |
| **转换（Transformation）** | 数据格式和内容的转换处理 |
| **增量（Increment）** | 识别和处理新增数据，避免全量处理 |
| **调度（Scheduling）** | 管理ETL任务执行的时间和顺序 |
| **监控（Monitoring）** | 追踪ETL执行状态和结果 |

### 定时执行策略

数据仓库系统中的数据不要求与[[OLTP]]系统中的数据实时同步，因此ETL可以定时进行。但多个ETL的操作时间、顺序和成败对数据仓库中信息的有效性至关重要。

---

## ETL与数据仓库分层

在大数据处理系统中，ETL是连接各层数据的桥梁。根据[[summaries/19.3.2数据管理]]，数据仓库通常分为以下层次：

| 层次 | 说明 | 开放程度 |
|------|------|----------|
| **ODS层** | 原始数据层，存放未经处理的原始数据 | 不对外开放 |
| **DWD层** | 明细数据层，对原始数据进行清洗和标准化 | 需申请访问 |
| **DWS层** | 服务数据层，汇总轻度汇总数据 | 需申请访问 |
| **ADS层** | 应用数据层，对外开放的数据表 | 对外开放 |

---

## 数据仓库类型与ETL目标

根据[[summaries/5.6.2数据仓库概述]]，从结构角度看有三种数据仓库模型：

### 企业仓库（Enterprise Warehouse）
- 面向企业级应用
- 搜集企业各个主题的所有信息，提供全企业范围的数据集成
- 数据来自多个操作型数据库和外部信息提供者，跨多个功能范围
- 通常包含详细数据和汇总数据，数据量可达TB级

### 数据集市（Data Mart）
面向部门级应用，包含企业数据的一个子集。根据数据来源分为：

- **从属数据集市（Dependent Datamart）**：数据直接来自中央数据仓库，有利于保持数据一致性，已经过一致性处理和检验
- **独立数据集市（Independent Datamart）**：数据直接来自业务系统。建立迅速、价格低廉，但后期整合到中心数据仓库时可能因各部门数据表达不一致而遇到困难

### 虚拟仓库（Virtual Warehouse）
操作型数据库上视图的集合，只有部分可能的汇总视图被物化。虚拟仓库易于建立，但需要操作型数据库服务器具有剩余工作能力。

## ETL规则元数据

根据[[summaries/19.3.2数据管理]]，**ETL规则元数据**是元数据管理的重要组成部分，主要涉及以下信息：

- **数据源元数据**：包括业务系统元数据和数据仓库元数据
- **目标系统元数据**：如数据仓库元数据、数据集市元数据
- **ETL流程**：各个模块的ETL处理过程及运行顺序
- **源与目标映射关系**：字段级别的数据对应关系

ETL规则元数据的管理主要由数据库开发人员根据各个模块的ETL过程以及过程运行的顺序，形成相关元数据管理文档进行统一管理。

## 数据血缘关系

### 血缘关系的定义

从技术角度来讲，数据a通过ETL处理生成了数据b，那么数据a与数据b具有血缘关系。血缘关系是[[数据治理]]中的核心概念，是在数据溯源过程中找到相关数据之间的联系，它是一种逻辑概念。

> "血缘分析是保证数据融合的一个手段，通过血缘分析实现数据融合处理的可追溯。大数据的数据血缘是指数据产生的链路。"

### 血缘关系的四个基本特征

根据[[summaries/19.3.2数据管理]]，血缘关系包含以下特征：

1. **归属性**：特定的数据归属特定的组织（或个人），数据具有归属性
2. **多源性**：同一个数据可以有多个来源，一个数据可以是多个数据经过加工而生成的，而且这种加工过程可以是多个
3. **可追溯性**：数据的血缘关系体现了数据的生命周期，体现了数据从产生到消亡的整个过程，具备可追溯性
4. **层次性**：数据的血缘关系是有层次的，对数据的分类、归纳、总结等进行描述的信息又形成了新的数据，不同程度的描述信息形成了数据的层次

### 数据质量传递

在数据的处理过程中，从数据源头到最终的数据生成，每个环节都可能会导致数据质量问题。例如：

- 数据源本身数据质量不高，在后续处理环节中没有进行质量检测，最终数据质量也不高
- 某个环节的数据处理中，对数据进行了不恰当的处理，导致后续环节数据质量变糟糕

因此，对于数据的血缘关系，要确保每个环节都注意数据质量的检测和处理，那么后续数据才会有优良的基因，即有很高的数据质量。

## 数据装载信息

根据[[summaries/19.3.2数据管理]]，**数据装载信息**是ETL过程中的重要元数据，记录每个ETL过程的详细信息：

- 抽取时间
- 操作人员
- 起始和截止时间
- 抽取涉及的表
- 操作行数

这些信息属于其他元数据的管理范畴，需要将元数据信息记录到日志，形成元数据文件进行统一管理。

---

## 数据源多样性

根据[[summaries/5.6.2数据仓库概述]]，数据仓库的数据源不仅限于企业内部的应用系统数据库。对于用于决策分析的系统而言，仅有企业内部数据是不够的。合理地采用外部数据能使分析和决策更为准确，这些外部数据包括：

- 报纸、期刊、电视等媒体的报道
- 商业机构的调查报告
- 行业研究数据

这些外部数据通常都是[[非结构化数据]]，如何用数据仓库管理非结构化数据是数据仓库应用中的重要问题。数据仓库采用[[元数据]]来管理非结构化数据，元数据可用于记录：

- 文件标识符
- 进入数据仓库的日期
- 文件描述
- 文件来源及取得日期
- 文件分类
- 索引字
- 清理日期
- 物理地址引用
- 文件长度和相关参考信息

## ETL架构模式

### 传统批处理ETL

- **定时执行**：按固定周期（如每日、每周）运行
- **适用场景**：数据仓库初始化、历史数据迁移
- **特点**：处理量大，但对实时性要求不高

### 流式ETL（实时采集）

- **持续处理**：数据流经系统即刻处理
- **代表技术**：Kafka作为数据消费者
- **特点**：分布式架构，满足每秒数百MB的日志采集需求
- **适用场景**：网络监控、金融交易、Web用户行为分析

根据[[summaries/19.3.1数据存储]]，流式ETL与传统批处理ETL的区别在于：

> "这个过程类似传统的ETL，但它是流式的处理方式，而非定时的批处理Job"

## 分布式数据库环境下的ETL

当ETL过程涉及[[分布式数据库]]时，需要处理[[数据分片]]带来的复杂性。根据分片方式的不同，ETL策略也有所调整：

### 水平分片数据的ETL

- 从多个物理节点并行抽取各分片数据
- 分片条件由关系属性值决定
- 重构全局数据时使用**并操作**合并结果
- 需处理分片间的数据一致性问题

### 垂直分片数据的ETL

- 按属性从不同节点抽取数据片段
- 通过**连接运算**重构完整数据
- 关键字属性需特殊处理
- 保证不相交性的约束

### 混合分片的ETL

- 结合水平分片和垂直分片的策略
- 需要多阶段处理：先按水平分片，再按垂直属性拆分
- 重构时需要先连接再合并

## 数据转换的六步骤

[[summaries/19.3.1数据存储]]详细描述了数据转换的六个行为步骤：

| 步骤 | 描述 |
|------|------|
| 1. 数据发现 | 使用分析工具理解数据特征和结构 |
| 2. 数据映射 | 定义字段映射规则（最耗时步骤） |
| 3. 数据提取 | 从原始来源提取数据 |
| 4. 代码生成 | 生成Python/R/SQL可执行代码 |
| 5. 代码执行 | 执行代码完成转换 |
| 6. 数据审查 | 验证输出是否符合要求 |

---

## 数据质量管理

ETL过程中的数据清洗是保证数据质量的关键，通常占据整个分析过程的**50%～80%**时间。数据清洗基本流程包括：

1. 数据分析 → 发现质量问题
2. 定义清洗策略和规则
3. 搜寻并确定错误实例
4. 纠正发现的错误
5. **干净数据回流**：替代原始"脏"数据

## 总结

ETL是构建企业级数据平台的基础架构，通过规范化的抽取-转换-加载流程，确保数据从源头到目的地的完整性、一致性和可用性。在大数据处理系统中，ETL不仅承担数据搬运的角色，更是[[数据治理]]和[[数据质量管理]]的核心支撑。

ETL的技术实现主要涉及关联、转换、增量、调度和监控五个核心环节。由于数据仓库不要求与OLTP系统实时同步，ETL可定时进行，但多个ETL操作的时间、顺序和成败对数据仓库信息的有效性至关重要。

在[[分布式数据库]]环境下，ETL需要适应[[数据分片]]带来的挑战，针对水平分片、垂直分片或混合分片采用不同的抽取策略，并通过并操作或连接运算完成数据重构。

现代数据仓库的数据源不仅限于企业内部数据库，还包括报纸、期刊、商业调查报告等外部数据，这些通常是非结构化数据。通过[[元数据]]管理，可以有效组织和追踪这些多样化的数据来源。

通过ETL规则元数据管理，系统可以追踪数据流转的完整链路；通过数据血缘关系分析，可以追溯数据来源、评估数据价值；通过数据装载信息记录，可以审计ETL执行过程。这些能力共同构成了现代大数据平台的数据治理基础设施。

现代大数据架构中，ETL正从传统的批处理模式向流批一体转型，实时性和灵活性成为新的发展方向。
