# 模块耦合

模块耦合（Coupling）是衡量软件系统中模块之间联系紧密程度的设计指标。在[[结构化设计]]方法中，耦合表示模块之间联系的程度，是评估软件系统质量的重要标准之一。

## 基本概念

耦合度描述了两个或多个模块之间相互依赖的程度：
- **紧密耦合**：模块之间联系非常强，修改一个模块可能影响多个模块
- **松散耦合**：模块之间联系比较弱，模块独立性较好
- **非耦合**：模块之间无任何联系，完全独立

在类的划分上，应当尽量创建松耦合的类，类之间的耦合度越低，就越有利于复用。一个处在松耦合中的类一旦被修改，不会对关联的类造成太大波动。

## 七种耦合类型

根据耦合度从低到高，模块耦合可分为7种类型：

| 耦合类型 | 描述 |
|---------|------|
| **非直接耦合** | 两个模块之间没有直接关系，通过主模块控制和调用实现联系 |
| **数据耦合** | 模块借助参数表传递简单数据 |
| **标记耦合** | 模块通过参数表传递记录信息（数据结构） |
| **控制耦合** | 模块之间传递的信息中包含用于控制模块内部逻辑的信息 |
| **外部耦合** | 模块访问同一全局简单变量，而非通过参数表传递 |
| **公共耦合** | 多个模块访问同一个公共数据环境（如全局数据结构、共享通信区） |
| **内容耦合** | 一个模块直接访问另一个模块的内部数据；不通过正常入口转到另一模块内部；两模块代码重叠；模块有多个入口 |

## 影响耦合强度的因素

模块之间耦合的强度主要依赖于：
1. 一个模块对另一个模块的调用程度
2. 一个模块向另一个模块传递的数据量
3. 一个模块施加到另一个模块的控制多少
4. 模块之间接口的复杂程度

## 降低耦合的设计原则

### 高内聚、低耦合原则

模块设计应追求**低耦合**，原因如下：
- 降低模块间的依赖性
- 提高模块的独立性和可维护性
- 减少修改一个模块对其他模块的影响
- 有利于模块的单独开发和测试

在[[结构化设计]]中，耦合与[[模块内聚]]共同构成评价模块质量的两个核心指标，遵循**"高内聚、低耦合"**的设计原则。

### 最少知识原则

[[最少知识原则]]的主要用途在于控制信息的过载。在类的设计上，只要有可能，一个类型应当设计成不变类；在对其他类的引用上，一个对象对其他对象的引用应当降到最低。这与低耦合目标高度一致。

### 设计模式的应用

[[设计模式]]是前人经验的总结，合理运用设计模式可以有效降低模块间的耦合度，提高系统的可复用性和灵活性。设计模式提供了一套经过分类编目的代码设计经验总结，通过应用成熟的设计模式，可以避免重复设计，使系统更加易于理解和维护。
