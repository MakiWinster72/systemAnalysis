# 信息系统故障分类体系

信息系统故障是指由于部件的失效、环境的物理干扰、操作错误或不正确的设计所引起的硬件或软件中的错误状态。在故障管理中，需要区分**故障**（引起错误的原因）与**错误**（故障在系统中的具体位置）这两个概念。

根据实践经验总结和有关统计数据，导致信息系统故障的原因可划分为七大类型，同时根据故障的表现形式，又可从时间特性角度进行分类，形成完整的故障分类体系。

## 一、硬件故障分类

### 按时间特性的三种表现形式

根据[[summaries/9.7.1系统故障模型]]的定义，硬件故障按其时间特性可分为三种表现形式：

| 类型 | 特征 | 修复可能性 |
|------|------|------------|
| **永久性故障** | 连续稳定的失效，反映不可恢复的物理改变 | 可修复（替换或重新设计） |
| **间歇性故障** | 由不稳定或临界稳定状态引起的偶然故障 | 可修复 |
| **瞬时性故障** | 由暂时环境条件引起的故障，硬件本身未损坏 | 不可修复（自动恢复） |

> **重要提示**：瞬时和间歇故障已经成为系统中的主要错误源，需要特别关注。

### 按错误表现形式的分类

硬件故障在数据级表现为差错，可分为：

- **独立差错**：一个故障使一个二进制位发生改变
- **算术差错**：一个故障使数据值增加或减少2ⁱ（i=0,1,2,…）
- **单向差错**：一个故障使二进制向量中的某些位朝一个方向（0或1）改变

### 按故障原因的七种类型

这一分类来自[[summaries/15.3.3故障排查和恢复处理]]中的故障原因调查环节，是[[故障管理]]工作中的重要参考依据。

#### 1. 计划性维护故障

按计划进行硬件、操作系统维护操作时引起的故障，例如：
- 扩充硬盘容量
- 进行操作系统升级
- 服务器更换配件

这类故障通常是可预见的，应提前做好[[故障排查和恢复处理|应急预案和数据备份]]。

#### 2. 应用性故障

与应用软件直接相关的故障，包括：
- 应用软件性能问题
- 软件缺陷（Bug）
- 系统应用变更导致的问题

应用性故障的[[故障定位]]相对复杂，通常需要通过软件调试定位错误代码行。

#### 3. 人为操作故障

由于人员操作不当导致的故障：
- 人员的误操作
- 不按规定进行的非标准操作

这类故障强调加强培训和完善操作规范的重要性。

#### 4. 系统软件故障

操作系统和基础软件层面的故障：
- 操作系统崩溃
- 数据库各类故障
- 驱动程序问题

系统软件故障可能影响整个[[故障管理]]流程，需要及时处理。

#### 5. 系统硬件故障

硬件设备物理损坏导致的故障：
- 硬盘损坏
- 网卡故障
- 路由器损坏
- 内存故障

硬件故障定位相对简单，计算机系统都配备了完善的诊断测试手段。

#### 6. 相关设备故障

与主系统相关但非核心硬件的设备故障：
- 停电时UPS失效导致服务中断
- 空调故障导致过热
- 电源模块故障

这类故障需要关注基础设施的冗余设计。

#### 7. 灾难和灾害

不可抗力因素导致的故障：
- 火灾
- 地震
- 洪水
- 战争

此类故障需要建立完整的[[故障排查和恢复处理|灾难恢复机制]]和业务连续性计划。

## 二、软件故障与软件差错

软件故障是指软件设计过程造成的与设计说明的不一致。与硬件不同，软件不会因为环境应力而疲劳，也不会因为时间的推移而衰老。因此，**软件故障只与设计有关**。

软件故障在数据结构或程序输出中的表现称为软件差错，常见的软件差错有以下几种：

| 类型 | 描述 |
|------|------|
| **非法转移** | 程序执行了说明中不存在的转移 |
| **误转移** | 程序执行了尽管说明中存在，但依据当前控制数据不应进行的转移 |
| **死循环** | 程序执行时间超过了规定界限 |
| **空间溢出** | 程序使用的空间超过了规定的界限 |
| **数据执行** | 指令计数器指向数据单元 |
| **无理数据** | 程序输出的数据不合理 |

## 三、系统级故障

故障在系统级上的表现为**功能错误**，即系统输出与系统设计说明的不一致。如果系统输出无故障保护机构，则故障在系统级上的表现就会造成**系统失效**。

系统级故障是[[故障排查和恢复处理]]中最需要关注的问题，因为它直接影响系统的可用性和用户的使用体验。

## 四、故障模型层级

故障的表现形式千差万别，可以利用故障模型对故障表现进行抽象。故障模型可在系统各个级别建立，一般来说，级别越低，故障处理代价越低，但覆盖的故障也越少。

### 逻辑级故障

硬件逻辑上出现的故障，表现为电路中元器件的输入或输出固定为0或1。包括：

- **短路故障**：元件输出线逻辑值恒等于输入线逻辑值
- **开路故障**：元件输出线悬空，逻辑值由具体电路决定
- **桥接故障**：两条不应相连的线连接在一起

### 数据结构级故障

故障在数据结构上的表现：

- **独立差错**：一个故障使一个二进制位发生改变
- **算术差错**：一个故障使数据值增加或减少2ⁱ（i=0,1,2,…）

## 五、系统可靠性指标与故障的关系

系统可靠性可以通过历史数据和开发数据直接测量和估算出来，与故障管理相关的核心指标包括：

### 平均无故障时间（MTTF）

**定义**：产品在规定的条件下和规定的时间内，完成规定功能的能力称为可靠性。可靠性的概率度量叫可靠度R(t)。MTTF定义为从t=0时到故障发生时系统的持续运行时间的期望值。

**公式**：MTTF = ∫₀^∞ R(t)dt

**当R(t) = e^(-λt)时**：MTTF = 1/λ（λ为失效率，单位时间内发生失效的预期次数）

**示例**：同一型号1000台计算机工作1000h，有10台故障 → R(1)=0.99，λ=10⁻⁵，MTTF=10⁵h

### 平均故障修复时间（MTTR）

**定义**：系统发生故障后平均需要的修复时间，用于衡量系统的可维护性。

### 系统可用性

综合反映MTTF和MTTR的综合指标，是衡量系统持续提供服务能力的重要参数。

> **实际意义**：通过监控和分析这些可靠性指标，可以预测系统可能发生的故障，从而采取预防措施，提升系统的[[系统可靠性]]。

## 六、故障分类的意义与应用

了解故障分类体系有助于：

1. **快速定位**：根据故障表现判断可能原因
2. **预防措施**：针对不同类型制定预防策略
3. **资源配置**：合理分配[[故障管理]]资源
4. **流程优化**：完善故障处理流程
5. **系统可靠性设计**：依据[[系统可靠性]]要求提升系统容错能力
6. **指标监控**：通过MTTF、MTTR等指标评估系统健康状态
