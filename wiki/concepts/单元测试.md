# 单元测试

单元测试（Unit Testing）是软件测试体系中最底层的测试活动，对软件中的最小可测试单元进行检查和验证。在基于构件的测试方法中，单元测试的主要目的是发现构件本身的错误，是保障[[软件构件]]可靠性的第一道防线。

## 概念定义

单元测试针对人为规定的最小被测功能模块进行验证。单元的具体含义因开发环境和语言而异：

- **C语言**：单元指一个函数
- **Java**：单元指一个类
- **图形化软件**：单元可指一个窗口或菜单

单元测试的核心原则是软件的独立单元将在与程序其他部分相隔离的情况下进行测试。

## 测试方法

单元测试以[[白盒测试]]技术为主，[[黑盒测试]]技术为辅。在构件测试语境下，单元测试的常用技术包括：

- **随机测试**：通过随机生成测试数据发现边界外问题
- **等价类测试**：将输入数据划分为有效和无效等价类
- **边界值测试**：重点测试边界条件下的行为
- **接口变异测试**：检验接口的正确性和健壮性

## 测试任务

单元测试的测试任务涵盖以下方面：

| 任务类型 | 说明 |
|----------|------|
| **内部验证** | 使用白盒测试确认构件的内部逻辑、数据和程序结构 |
| **功能验证** | 使用黑盒测试确认构件的外部功能、行为和接口 |
| **性能度量** | 测量构件的执行性能和资源消耗 |
| **结果报告** | 报告测试结果、程序错误和测试覆盖率 |

## 测试内容

单元测试主要包含以下五个方面的测试：

1. **模块接口测试**：验证模块输入输出的正确性
2. **局部数据测试**：检验局部数据结构和变量
3. **路径测试**：覆盖程序中的关键路径
4. **错误处理测试**：验证异常情况的处理能力
5. **边界测试**：检验边界条件下的行为

## 测试数据

进行单元测试时使用的数据通常不使用真实数据。当被测单元需要操纵大量数据，且多个单元都有此需求时，可考虑使用正式数据的一个较小有代表性的样本。

## 测试规定

| 项目 | 内容 |
|------|------|
| **测试阶段** | 编码后或编码前 |
| **测试对象** | 模块或构件 |
| **测试人员** | 白盒测试工程师或开发人员 |
| **测试依据** | 代码、注释和详细文档 |
| **测试方法** | 白盒测试为主，黑盒测试为辅 |

## 执行角色

单元测试一般由开发人员本身完成，并在开发组组长的监督下进行。这与其他高层测试主要由专职测试人员执行有所不同。

## 构件测试中的单元测试

在基于[[软件构件]]的测试过程中，单元测试对应构件开发阶段的"构件鉴定"环节。这一阶段需要验证：

- 构件是否按照需求规约构造
- 构件是否符合构件标准和模型要求
- 构件本身的错误是否被发现和修复

## 测试阶段定位

单元测试是软件开发过程中进行的最低级别测试活动，属于[[软件测试]]金字塔的基石部分，承接上游的编码工作，为[[集成测试]]提供基础。

## 相关概念

- [[集成测试]]：单元测试之后，测试模块间接口
- [[系统测试]]：集成测试之后，测试整个系统
- [[验收测试]]：发布前最终验证
- [[白盒测试]]：单元测试主要采用的方法
- [[黑盒测试]]：单元测试辅助采用的方法
- [[软件构件]]：单元测试的主要对象之一
