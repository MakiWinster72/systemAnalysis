## 数据库数据恢复技术

数据库数据恢复技术是数据库系统可靠性保障的最后一道防线。无论安全措施多么完善，数据被破坏的情况仍可能发生——可能源于人为操作失误、硬件设备故障、软件系统崩溃，甚至自然灾害。数据恢复技术的核心目标就是当数据被破坏后，在一定时间内将数据库调整到破坏前的正确状态。

### 核心原理：冗余

数据恢复的基本原理是**冗余**。通过建立数据冗余，即使原始数据丢失，也能从冗余副本中恢复。实现冗余的主要方法包括：

- **数据备份**：定期复制数据库内容
- **[[事务日志]]**：记录对数据库的每一次更新活动

### 备份类型

#### 按实现方式划分

| 类型 | 说明 |
|------|------|
| **[[物理备份]]** | 在操作系统层面对数据文件进行备份 |
| **[[逻辑备份]]** | 利用DBMS自带工具备份数据内容（如Oracle的exp/imp） |

#### 按备份状态划分

| 类型 | 说明 |
|------|------|
| **[[冷备份]]**（静态备份） | 数据库正常关闭后，在停止状态下备份文件。最快最安全，但备份期间数据库不可用 |
| **[[热备份]]**（动态备份） | 数据库正常运行状态下备份。可达秒级恢复，但不允许失败 |

#### 按数据量划分

| 类型 | 说明 |
|------|------|
| **完全备份** | 将整个数据库中的数据进行备份 |
| **[[增量备份]]** | 备份上一次备份后发生变化的数据 |
| **[[差异备份]]** | 备份上一次完全备份后发生变化的所有数据 |

### 事务日志的作用

[[事务日志]]是针对数据库改变所做的记录，完整保存了对数据库的每一次操作。对于任何一个事务，事务日志都有非常全面的记录，根据这些记录可以将数据文件恢复到事务前的状态。

日志记录的主要内容包括：
- 执行操作的事务标识
- 操作类型（插入、删除、修改）
- 更新前数据的旧值（对插入操作为空值）
- 更新后的新值（对删除操作为空值）

### 先写日志原则

恢复机制必须严格遵循**先写日志文件**的规则：

> 在将修改写入数据库之前，必须首先将修改记录写到日志文件上，然后再写数据库的修改。

这是因为写数据库修改和写日志记录是两个独立的操作，可能在其中一个完成后发生故障。若先写了数据库修改而日志中没有登记，则无法恢复这个修改。

### 数据恢复策略

数据恢复可根据故障的不同类型采用不同的策略，包括[[事务处理]]故障、系统故障和介质故障等。

#### 事务故障恢复

由系统自动完成，对用户透明（不需要DBA参与）：
1. 反向扫描日志文件，查找该事务的更新操作
2. 对更新操作执行逆操作
3. 继续反向扫描并处理其他更新操作
4. 直至读到此事务的开始标记

#### 系统故障恢复

系统故障的恢复在系统重新启动时自动完成，不需要用户干预。步骤如下：

1. **正向扫描日志文件**，找出在故障发生前已经提交的事务，将其事务标识记入**重做(Redo)队列**
2. 同时找出故障发生时尚未完成的事务，将其事务标识记入**撤销(Undo)队列**
3. 对撤销队列中的各个事务进行**撤销处理**：反向扫描日志文件，对每个Undo事务的更新操作执行逆操作
4. 对重做队列中的各个事务进行**重做处理**：正向扫描日志文件，对每个Redo事务重新执行日志文件登记的操作

#### 介质故障恢复

介质故障与病毒破坏的恢复步骤如下：

1. 装入最新的数据库后援副本，使数据库恢复到最近一次备份时的一致性状态
2. 从故障点开始反向扫描日志文件，找出已提交事务标识并记入Redo队列
3. 从起始点开始正向扫描日志文件，根据Redo队列中的记录，重做已完成的任务，将数据库恢复至故障前某一时刻的一致状态

#### 检查点恢复技术

检查点记录的内容可包括：建立检查点时刻所有正在执行的事务清单，以及这些事务最近一个日志记录的地址。采用检查点的恢复步骤如下：

1. 从重新开始文件(Redo Log)中，找到最后一个检查点记录在日志文件中的地址
2. 由该地址在日志文件中找到最后一个检查点记录
3. 由检查点记录得到检查点建立时所有正在执行的事务清单队列(A)
4. 建立重做队列(R)和撤销队列(U)，将A队列放入U队列中，R队列为空
5. 从检查点开始正向扫描日志文件：
   - 若有新开始的事务T₁，则将T₁放入U队列
   - 若有提交的事务T₂，则将T₂从U队列移到R队列
   - 直至日志文件结束
6. 对U队列的每个事务执行Undo操作，对R队列的每个事务执行Redo操作

检查点恢复技术通过减少日志扫描范围，显著提高了故障恢复的效率。

### 备份策略设计原则

制定备份和恢复策略时应遵循：
- 保证数据丢失尽量少或完全不丢失
- 备份和恢复时间尽量短
- 保证系统最大的可用性

实践中，通常将完全备份与增量、差异备份组合使用。一个备份周期通常由一个完全备份和多个增量/差异备份组成。
