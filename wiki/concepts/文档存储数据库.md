# 文档存储NoSQL数据库

## 定义

文档存储NoSQL数据库是一类以[[文档]]为单位组织和存储数据的非关系型数据库。它们属于[[NoSQL非关系数据库]]的重要分类之一，采用类似[[JSON]]的格式存储文档型数据。

## 核心特点

### 数据模型
- 以文档（通常使用[[JSON]]或[[BSON]]格式）为存储单位
- 不需要固定的表结构，文档可以像定义了表结构一样来使用
- 文档可以很长、很复杂、无结构，可以是任意结构的字段
- 数据具有物理和逻辑上的独立性

### 技术优势
- **结构灵活**：文档结构可根据业务需求动态调整
- **可构建索引**：能够根据value（而非仅键）构建索引，支持复杂查询条件获取数据
- **自然的数据表示**：文档格式与面向对象编程天然契合
- **嵌入数据处理**：支持JSON、XML等可嵌入数据的快速处理功能

## 典型产品

### [[MongoDB]]
MongoDB是由10gen公司开发的高性能、可扩展的文档数据库，是NoSQL文档存储模式中最重要的产品之一。

**核心特性：无表结构**
- 将数据和数据结构完整地以BSON形式保存
- BSON是JSON的二进制编码格式，支持更复杂的格式，空间利用更高效
- 数据作为值与特定键进行关联，无需预先定义表结构

**四大特性：**

| 特性 | 说明 |
|------|------|
| **高性能** | 提供JSON/XML等嵌入数据快速处理；文档索引功能显著提高查询速度 |
| **丰富的查询语言** | 支持数据聚合、结构文档、地理空间等丰富的查询功能 |
| **高可用性** | 提供数据冗余处理和故障自动转移功能 |
| **水平扩展能力** | 通过集群将数据分布到多台机器，支持主从和副本集两种模式 |

MongoDB为C、C#、.NET、Java、PHP等各种开发语言提供了程序库。

### [[CouchDB]]
采用[[HTTP]] RESTful API接口，支持最终一致性模型。

## 应用场景

- **[[Web应用]]**：适合存储面向文档的数据
- 半结构化数据存储：结构灵活，可根据value构建索引
- 内容管理系统
- 用户配置文件管理
- 日志和分析数据
- 地理空间数据应用

## 与关系数据库对比

| 特性 | 文档数据库 | 关系数据库 |
|------|-----------|------------|
| 存储单位 | 文档 | 行 |
| 数据结构 | 灵活、无需预定义 | 高度结构化（表结构） |
| 查询能力 | 支持复杂查询条件 | 支持JOIN、事务处理 |
| 数据完整性 | 不提供参照完整性 | 提供完整约束支持 |
| 事务处理 | 缺乏分布式事务支持 | 支持ACID事务 |
| 适用场景 | 大量半结构化数据 | 强一致性需求 |

两者之间并不排斥，在实际应用中可以进行数据交换和互补使用。
