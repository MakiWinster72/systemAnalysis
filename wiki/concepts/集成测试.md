# 集成测试

集成测试（Integration Testing）是将软件模块组装后进行的测试活动，又称**子系统测试**、**组装测试**或**部件测试**。它主要针对软件高层设计，以模块和子系统为单位进行验证。

## 测试层次

集成测试包含三个层次：

1. **模块内集成** — 测试模块内各个接口间的交互集成关系
2. **子系统内集成** — 测试子系统内各个模块间的交互关系
3. **系统集成** — 测试系统内各个子系统和模块间的集成关系

## 测试规定

| 项目 | 内容 |
|------|------|
| 测试阶段 | 单元测试之后 |
| 测试对象 | 模块间的接口 |
| 测试人员 | 白盒测试工程师或开发工程师 |
| 测试依据 | 单元测试文档、概要设计文档 |
| 测试方法 | 黑盒测试、白盒测试、灰盒测试 |

## 测试内容

- 模块之间数据传输
- 模块之间功能冲突
- 模块组装功能的正确性
- 全局数据结构
- 单模块缺陷对系统的影响

## 与其他测试阶段的关系

集成测试位于软件开发测试流程的中间环节：
- 承接 [[summaries/14.4.2按测试阶段划分|单元测试]] 的结果
- 为 [[系统测试]] 提供已组装完成的软件系统
- 最终服务于 [[验收测试]]

## 测试方法选择

集成测试可根据需要灵活选用不同测试方法：
- [[白盒测试]]：关注内部逻辑和代码结构
- [[黑盒测试]]：关注输入输出和功能行为
- [[灰盒测试]]：结合两者优势，关注接口协议和部分内部实现

## 核心目标

集成测试的核心目标是发现模块组装过程中的问题，确保各个模块组合后能够正确协同工作，验证模块间的接口契约和数据交互是否符合预期设计。
