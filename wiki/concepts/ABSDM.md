# 基于架构的软件开发模型（ABSDM）

## 定义

基于架构的软件开发模型（Architecture-Based Software Development Model, ABSDM）是一种将软件体系结构设计贯穿整个软件开发生命周期的系统化方法。该模型克服了传统软件开发模型效率不高、难以支持软件重用的缺点。

## 核心问题

传统软件开发模型存在以下缺陷：
- 开发效率不高
- 不能很好地支持软件重用
- 软件体系结构建立时间较晚，通常位于需求分析之后、概要设计之前

## ABSDM的6个阶段

ABSDM将基于体系结构的软件过程划分为6个子过程：

| 阶段 | 说明 |
|------|------|
| [[summaries/12.5.1体系结构需求]] | 获取用户需求，标识系统中所要用到的构件 |
| 体系结构设计 | 基于需求进行架构设计 |
| 体系结构文档化 | 记录和传达架构决策 |
| 体系结构复审 | 评估架构方案的质量和适用性 |
| 体系结构实现 | 根据架构指导具体编码实现 |
| 体系结构演化 | 随需求变化演进架构 |

## 体系结构需求详解

体系结构需求阶段包含两个核心活动：

### 1. 需求获取

体系结构需求的三大来源：
- **系统的质量目标**：性能、可靠性、安全性等非功能需求
- **系统的商业目标**：业务价值、市场竞争力等
- **系统开发人员的商业目标**：开发效率、成本控制等

### 2. 标识构件

标识构件过程为系统生成初始逻辑结构，可分为三步：
1. 生成类图（CASE工具如Rational Rose 2000）
2. 对类进行分组
3. 把类打包成构件

## 与传统模型的比较

| 方面 | 传统模型 | ABSDM |
|------|----------|--------|
| 架构介入时机 | 概要设计前 | 需求阶段即开始 |
| 开发效率 | 相对较低 | 较高 |
| 软件重用 | 支持有限 | 原生支持 |
| 需求复用 | 无专门机制 | 需求库支持 |
