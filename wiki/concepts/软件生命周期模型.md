# 软件生命周期模型

## 定义

软件生命周期模型（Software Lifecycle Model）是描述软件产品从概念形成、需求分析、设计、实现、测试、部署、维护到最终废弃的完整过程中各个阶段的划分、组织和管理方式的框架。

## 主要生命周期模型

### 1. 瀑布模型（Waterfall Model）

最经典的结构化开发模型，按照严格的线性顺序执行：

**阶段流程**：需求分析 → 软件设计 → 程序编码 → 软件测试 → 运行维护

**特点**：
- 每个阶段完成后才进入下一阶段
- 强调文档驱开发
- 适用于需求明确、变化少的项目

**优点**：
- 阶段清晰，便于管理
- 早期发现问题成本较低
- 适合CMM/CMMI体系下的规范化管理

**缺点**：
- 缺乏灵活性，难以应对需求变化
- 客户只能在最后阶段看到产品
- 风险在后期才能暴露

### 2. 增量模型（Incremental Model）

将系统功能分解为多个增量模块，分批逐步交付：

**特点**：
- 第一个增量往往是核心功能
- 每个增量都是可运行的子系统
- 允许需求变化

**优点**：
- 客户可以尽早使用部分功能
- 降低项目失败风险
- 适应需求不确定的项目

**缺点**：
- 需要开放式架构设计
- 可能导致系统架构质量下降

### 3. 螺旋模型（Spiral Model）

结合瀑布模型与迭代模型，强调风险分析：

**四个主要活动**：
1. 确定目标、约束条件
2. 识别、解决风险
3. 开发下一阶段产品
4. 评审前阶段成果，规划下一循环

**特点**：
- 每个循环都包含风险分析
- 适合大型复杂系统
- 支持多次迭代

### 4. 敏捷开发模型（Agile Development）

以人为核心，快速响应变化的迭代开发方法：

**核心价值观**：
- 个体与互动 高于 流程与工具
- 可工作软件 高于 详尽文档
- 客户合作 高于 合同谈判
- 响应变化 高于 遵循计划

**常见框架**：
- [[summaries/2025下半年系统分析师速记50个高频知识点|Scrum]]：角色分工（Product Owner、Scrum Master、Team）、Sprint周期、每日站会
- 极限编程（XP）：结对编程、持续集成、测试驱动开发
- 看板（Kanban）：可视化工作流、限制在制品数量

**适用场景**：
- 需求变化频繁
- 小型至中型团队
- 追求快速交付

## 模型选择指南

| 项目特征 | 推荐模型 |
|---------|---------|
| 需求稳定明确 | 瀑布模型 |
| 需求有变化可能 | 增量模型 |
| 大型复杂高风险项目 | 螺旋模型 |
| 需求不确定、变化频繁 | 敏捷开发 |
| 需快速交付MVP | 增量模型+敏捷 |

## 考试要点记忆

1. **瀑布模型**：线性顺序、文档驱动、阶段清晰
2. **增量模型**：分批交付、适应变化、模块化
3. **螺旋模型**：风险驱动、迭代循环、适合大型项目
4. **敏捷开发**：人本主义、快速迭代、响应变化
