# 函数依赖

## 定义

设 R(U) 是属性集 U 上的关系模式，X 和 Y 是 U 的子集。若对于 R 的任意关系 r 中的任意两个元组 u、v，只要满足 **u[X] = v[X]**，就能推出 **u[Y] = v[Y]**，则称 **X 函数决定 Y** 或 **Y 函数依赖于 X**，记作 **X → Y**。

例如，员工关系中的 EMP_NO → EMP_NAME 表示员工号唯一决定员工姓名。

## 函数依赖的类型

| 类型 | 定义 | 示例 |
|------|------|------|
| **完全函数依赖** | X → Y，且对于 X 的任何真子集 X'，X' → Y 都不成立 | (Sno, Cno) → Grade（假设同学生不能同时选修同一课程） |
| **部分函数依赖** | X → Y，但 Y 不完全函数依赖于 X，即存在 X 的真子集 X' 使得 X' → Y | (Sno, Cno) → Credit（Cno 单独就能决定 Credit） |
| **传递函数依赖** | X → Y（Y 不是 X 的真子集），Y → X 不成立，但 Y → Z | Sno → Dno → Dname（Sno 通过 Dno 传递决定 Dname） |

## 函数依赖与键的关系

函数依赖是确定[[候选键]]的基础：

- 若 X → U 在 R(U) 上成立，且不存在 X 的真子集 X' 使 X' → U 成立，则 X 是 R 的**候选键**
- 在多个候选键中选定的为主键
- [[外键]]则是引用其他关系主键的公共属性

## 求候选键的图示法

1. **画出有向图**：顶点表示属性，弧表示函数依赖关系
2. **找入度为 0 的属性**：这些属性不能由其他属性决定
3. **遍历验证**：以入度为 0 的属性集为起点，尝试遍历所有顶点
4. **逐步扩展**：若不能遍历完所有顶点，则逐步加入中间顶点（既有入度也有出度的顶点）

例如，关系 R(A1, A2, A3, A4) 上的函数依赖集 F = {A1→A2, A2→A3, A3→A4, A4→A1} 中，A1 的入度为 0，以 A1 为起点可遍历所有顶点，因此 A1 是候选键。

## 函数依赖与范式

函数依赖决定了关系模式属于哪种[[范式]]：

- **1NF**：属性只包含原子值
- **2NF**：满足 1NF，且每个非键属性完全依赖于候选键（无部分函数依赖）
- **3NF**：满足 2NF，且非键属性不传递依赖于候选键
- **BCNF**：每个函数依赖的左部都必须包含候选键

## 核心要点

1. 函数依赖是数据库的一种**约束**，描述了属性间的语义联系
2. 完全函数依赖保证了数据的最小冗余
3. 部分函数依赖和传递函数依赖是导致数据库异常的根本原因
4. 规范化过程通过分解关系模式来消除不合理的函数依赖
